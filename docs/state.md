## `kq_facts`：关于快期模拟这个口子的已实测事实

⚠️ **这一节与 `rules_measured` 是两回事，分开记是刻意的。**

交易日 20260908 的夜盘量到下表这些，而 [cn-futures-rules.md](./cn-futures-rules.md) §13
那张待实测表只划掉了一条。原因不是量得不够，是两个问题不同：

> 这里记的是「**快期模拟怎么实现**」；§13 问的是「**规则是什么**」。
> 前者是后者的证据来源之一，不是后者的答案。

把它们记在同一个数里，就会出现「实测 6 条」这样的说法，
而读的人会以为规则定了 6 条。**一个把两种东西合并的计数，比没有计数更坏。**

⚠️ 第 16–19 条来自**成交截面第一次进夹具**之后的日盘批（自然日 2026-09-08 13:2x–13:4x）。
在此之前夹具只存持仓截面，也就是只存了均价 —— 而第 16 条问的正是「均价是怎么来的」，
第 17/18/19 条问的是逐笔的费额。**这些问题此前不是没答案，是问不出来。**

⚠️ 第 13/14/15 条是**读夹具读出来的**，不是新做实验得来的：
同一批 188 份截面此前只被逐条看过，没被**横着**统计过。
一个「量了就算用过了」的默认，会让已经付过代价的数据白放在那里。

⚠️ 第 13 条与第 15 条合起来才是完整的：`"-"` **在均价与保证金上是状态的函数，
在成本与盈亏上不是**。只记住前半句，就会把成本字段的 `"-"` 也当成「空仓」的同义词，
而那会在「当天平过仓」的合约上错。

⚠️ 第 4 条是本批唯一一条**已知与真实柜台不同**的，而它的偏差在同一天内是常数，
因此对拍时最容易被读成「对上了」。它必须进对拍的**已知差异表**，不能当成通过。

⚠️ **二十一条事实里只有第 7 条进了 `rules_measured`，这条线是刻意画的：**
第 7 条有**两个独立来源同向**——快期实测，加上 CTP 接口文档里同一条公式。
其余十九条里只有第 20 条有第二个来源，而它证的是「某几个合约在某一天的结算价是多少」，不是一条规则；余下十九条只有快期一个来源，而本批恰恰量到快期在手续费基准价上偏离 CTP，
所以「快期这样」不能直接读成「规则如此」。
**判据是「有没有第二个独立来源」，不是「量得准不准」。**

理由，逐条可查：

1. **那个值本来就是公开的**——它在 `shinnytech/tqsdk-python` 的 `tqsdk/auth.py`
   里，本库正是从那里读到的。它是**该 SDK 分发给所有使用者的客户端身份**，
   不是任何人的凭据，单凭它拿不到任何账户。
2. **重写的代价是实的**：`dev` 与 `main` 全部 SHA 作废，评审会话正在追踪的引用
   全部失效。
3. ⚠️ **重写的收益是虚的**：兄弟仓 `futures-tickflow-go` 做过重写并**当场复验**——
   旧 SHA 经 GitHub API **仍返回 200**（GitHub 对弃置对象保留一段时间）。
   所以那是「大幅降低」不是「彻底消除」。
4. **向前不再分发已经做到**：当前代码从 `.env` 读，缺失时报错，
   `git grep` 与 `git log -S` 均已复核。

⚠️ **措辞按第 3 条来。** 本文档不写「已彻底移除」——那会是又一次
「声称做过某事」而没有验证路径，正是 [silent-risks.md](./silent-risks.md)
方法论第 5 条要防的东西。

各状态键翻转后，下列字符串不得再作为**现时叙述**出现（只允许出现在

### ⚠️ 自指豁免必须在写脚本**之前**定死

拿上面这张表在全库真跑一遍，命中 **6 处**，全部合法：

| 位置 | 为什么合法 |
|---|---|
| `probes.md` 两处 | 历史留档，记录「当时缺什么」 |
| `roadmap.md:143` | **列举禁语的那一句** |
| `roadmap.md:180` | 分析「哪条机制抓得住哪一类」的表 |
| `roadmap.md:354` | 变更记录引用历史原文 |
| 删除线内一处 | 已显式作废 |

⚠️ **一个永远红的检查会被忽略，被忽略的检查等于没有检查。**
它和「有人去刷 `restatement-count.sh` 那个数」是同一种死法——
只是这次死于**噪声**，那次死于**粉饰**。

所以豁免规则现在就定死，**不等它红了再补 `# nolint`**——补出来的豁免会越加越宽：

> **禁语只在「正文叙述行」上生效。** 一行是正文叙述行，当且仅当它
> ① 不在代码块（``` 围栏）内；
> ② 不在历史留档块内。⚠️ **标记的判定是「整行就是它」，不是「行内含有它」**
>   ——本文件在定义标记时必然要提到它们，按「含有」判定会把定义行读成未闭合的
>   块，于是本文件结束时深度不为零。这与「字典必然包含它定义的每一个词」是
>   同一个形状，只是从禁语层跑到了标记层，而它暴露的是**「怎么算一个标记」
>   当时根本没写**——两个实现可以在这里分道扬镳，且两条都读得通；
> ③ 不含删除线 `~~`；
> ④ **位于本文件（`state.md`）内，或含指向 `state.md` 的链接**。

第 ④ 条的后半句是刻意设计的：讲这套机制的段落**本来就该引用唯一来源**。

⚠️ **前半句是补上的，而它暴露了一个形状**：唯一来源建起来之后，
它成了全库**唯一必然违反禁令的文件**——字典必然包含它定义的每一个词。
而规则是在它存在之前写的，所以漏掉了字典自己。

⚠️ 更糟的是这条排除起初**只存在于实现里**：我第一版检查器写了
`if p.endswith('state.md'): continue`，规则里一个字没有。
于是我跑出 0 处、评审跑出 4 处，**分歧的根源不是实现有 bug，是规范缺一条**。
于是豁免不是特批，是**挣来的**——你要谈禁语，就得同时把读者指回 `state.md`。
⚠️ 历史留档的标记也据此从散文（「以下保留原文」）改成了机器可读的 HTML 注释；
散文标记脚本读不懂，而读不懂的结果是**误报**，误报的结果是被忽略。

### 落成脚本时的「守卫的守卫」

标记本身会写错。2026-09-07 `probes.md` 就出过 `start=3 / end=2`——
把标记「提到标题之前」时加了新的、没删旧的。

⚠️ **这个毛病的失败方向朝着「什么也不报」**：深度计数式实现下，
`probes.md` 结束时 depth=1，若不逐文件重置，按字母序排在它后面的
`roadmap.md` / `silent-risks.md` / `state.md` **会被整体豁免掉**。
0 处不是因为干净，是因为检查在半路闭了嘴。

**一个豁免机制出 bug，比检查本身出 bug 更糟：它让检查更安静，不是更吵。**

所以脚本必须自己断言：

1. 每文件 `start == end`，**不配平直接失败并指出文件名**
2. 不允许嵌套（深度只能是 0 或 1）
3. EOF 时深度归零
4. **逐文件重置块状态**，绝不跨文件带

⚠️ **禁语只防复发，不防首发。** 它是一份对自然语言的黑名单，而黑名单漏一条即静默失效。
禁语从**状态翻转那次提交里被删掉的字符串**中生成——列表由真实编辑长出来，
不由想象力长出来。**首次写出一句新的过期表述，仍然只能靠人眼。**
