## ✅ `rules_pending` #6 的 CTP 那一半开了口（20260910 夜盘）

**新工具 `oracle ctp-reject`**：一张**写死的**非法报单清单，逐条发出去记数值码。
⚠️ 每条都**双重安全** —— 既非法、**即使被放过也成不了交**：买单挂低价、卖单挂高价。
（判据写在 `rejectCases` 的注释里；反过来的组合会当场成交，
而一个只想被拒的探针变成一次真实开仓，**在日志里与成功的探针长得一模一样**。）

    实测四条，**没有任何一条成交**

### ⚠️ 拿到的不只是码，是**两个码空间**

    CTP 码（RspInfo.ErrorID）        SHFE 码（在 StatusMsg 的文本前缀里，而 ErrorID = **0**）
      22  不允许重复报单               48  价格非最小变动价位的倍数
      50  平今仓位不足                 49  价格超出涨停板
      51  平昨仓位不足                 50  价格跌破跌停板

⚠️⚠️ **两套码撞号**：`CTP 50 = 平今仓位不足`，`SHFE 50 = 价格跌破跌停板` ——
**同一个数，两个完全不同的意思。**

> ⚠️ 一个按「50」建表的 `ctperr`，会把「仓位不足」与「价格越界」并成一条 ——
> **而它不会报错，只会在某一天把一个拒因解释成另一个。**

⇒ `ctperr` 的取值现在有语料了，⚠️ **而第一条设计约束也随之确定：
它必须带「码空间」这一维，不能只有一个整数。**

### ⚠️ 第二个发现：`ErrorID == 0` **不代表「没有拒单」**

    价格类三条  确实被拒，而 RspInfo.ErrorID **是 0**，码在文本前缀里
    仓位不足    走 ErrRtn，RspInfo.ErrorID = 51

⇒ **交易所级的价格类拒单根本不经过 `RspInfo`。**判「有没有被拒」要看
`Status`（`OST_Canceled`）与 StatusMsg，**不能看 ErrorID 是不是 0**。

⚠️ 而这一条**当场否掉了我二十分钟前刚写下的一句注释**：
我在把 `ErrorID` 接出来时写「只填交易所那条的话，柜台级的拒因会以 ErrorID=0 出现，
**而 0 是「没有拒单」的取值** ⇒ 一次真的拒单看起来像成功」——
**前半句对，后半句错**：0 不只出现在「没填」的情形，它是价格类拒单的**正常取值**。
已就地更正（`cmd/oracle/ctp/send_windows.go`）。

> ⚠️ **一句关于「这个零意味着什么」的推断，写下二十分钟就被同一晚的测量否掉。**
> 而它当时读起来完全成立 —— 因为我只见过走 `RspInfo` 的那一类拒单。

## ✅ 判别实验 #3 答了：**单向大边按「品种」合并** —— 事前登记与结果

`rules_pending` #3 原话：「⚠️ **换口子**：快期模拟根本没实现大边，此问题在该口子上**测不出来**」。
⇒ CTP/SimNow 是那个换来的口子，而白银夜盘到 02:30，`ag2701` 与 `ag2702` 都活着。

### 做法

    开 SHFE.ag2701 **多** 1 手 + SHFE.ag2702 **空** 1 手（同品种、不同月份）
    读同一份截面里：每条腿的 `UseMargin`（U1 / U2）与账户的 `CurrMargin`

### ⚠️ 判据（观测后不许改）

    候选 A  无大边 / 按**合约**   CurrMargin = **U1 + U2**
    候选 B  有大边 / 按**品种**   CurrMargin = **max(U1, U2)**
    候选 C  其他                  ⚠️ **如实记下那个数，不往 A/B 上凑**
            （有的口径是 max(大边) + 小边×某比例，本库没建模过它）

⚠️ **判别力要求 U1 ≠ U2** —— 两个月份价格不同，标准保证金随价走，应当自然满足；
**若恰好相等，这一轮什么都没分开，如实记「未触发」。**

⚠️ 而本条**不需要事先知道费率**：两个候选都只用同一份截面里的三个数
（U1 / U2 / CurrMargin），⇒ **没有跨夹具借值的余地**，这是 ① 那次的教训。

### ⚠️ 为什么这条值得花两手仓

    影响面（§13 原文）  跨期套利的保证金，**可能差一倍**
    v0.5.0 的核心       MaxMarginSideAlgorithm 是逐合约的规则数据，
                        而本库 margin 包的 `MaxMarginSide` 字段**至今没有观测支撑**

⚠️ 而 `rules_pending` #14 记着「公司与交易所口径在**全部数据源上都分不开**」——
本条若测出大边，那是**第一次**有一个保证金规则在 CTP 侧被分开。

### ✅ 手续费的形状：四个品种，同一个加性公式

    rb  名义×0.0001  + 每手 **0.005**
    i   名义×0.0001  + 每手 **0.005**
    ag  名义×0.00001 + 每手 **0.005**
    m   名义×0       + 每手 0.2

⚠️ **三个不同品种、三种不同的按金额费率，而每手那一项都是 0.005** ——
⇒ 那更像一项**与品种无关的固定收费**（保障基金之类），而不是品种费率的一部分。

### ⚠️ #5 仍然分不开，而现在能说清**为什么**

    每一笔观测都是  整数价 × 乘数 × 费率 + 每手项
    rb   价×10×0.0001  = 价×0.001    ⇒ 至多 3 位
    i    价×100×0.0001 = 价×0.01     ⇒ 至多 3 位（tick 0.5）
    ag   价×15×0.00001 = 价×0.00015  ⇒ 至多 **5 位**

⇒ **「不取整」与「取到 N 位」在 N ≥ 5 时给出同一个数** ——

⇒ 要分开它，需要一个**费率粒度更细**的品种，不是更多样本。
⚠️ **这比「分不开」有用**：它把一个模糊的盲区变成了一条**采样条件**。

#### 记账那一笔为什么要两个分母

第 37 条**从没被写进 §13** —— 它不是解决了一条挂着的未知，是回答了一个没人问过的未知。而 `rules_pending` 只数**还欠着的**（已收敛的行划掉、不在册）。于是两个方向会叠在一起：

    只记「解决」不记「发现」    分子涨、分母不动
    已收敛的行离开 pending      分子涨、分母**缩**

### 落成脚本时的「守卫的守卫」

标记本身会写错。2026-09-07 `probes.md` 就出过 `start=3 / end=2`——
把标记「提到标题之前」时加了新的、没删旧的。

⚠️ **这个毛病的失败方向朝着「什么也不报」**：深度计数式实现下，
`probes.md` 结束时 depth=1，若不逐文件重置，按字母序排在它后面的
`roadmap.md` / `silent-risks.md` / `state.md` **会被整体豁免掉**。
0 处不是因为干净，是因为检查在半路闭了嘴。

**一个豁免机制出 bug，比检查本身出 bug 更糟：它让检查更安静，不是更吵。**

所以脚本必须自己断言：

1. 每文件 `start == end`，**不配平直接失败并指出文件名**
2. 不允许嵌套（深度只能是 0 或 1）
3. EOF 时深度归零
4. **逐文件重置块状态**，绝不跨文件带

⚠️ **禁语只防复发，不防首发。** 它是一份对自然语言的黑名单，而黑名单漏一条即静默失效。
禁语从**状态翻转那次提交里被删掉的字符串**中生成——列表由真实编辑长出来，
不由想象力长出来。**首次写出一句新的过期表述，仍然只能靠人眼。**
