# F9c：K线撮合实现设计

本稿补充 design.md 门面形状 §13，基于已完成的 F9a 与 F9b。今日 P-resting-price 尚未执行；本稿先准备架构与测试，不提前宣称成交价已实测。当前工作状态以 [state.md](./state.md) 为准。

## 口径与存档

Choices 增加第九项 RestingFill，枚举为未指定、触价即成、穿价才成。两个预设都不替调用方填写；New 接受零值，使纯记账与手动 Fill 用户仍可使用，但 Advance 撮合入口即使空簿也拒绝零值。非法非零枚举在 New 就拒绝。先完成原有 K线守卫，再检查撮合口径，再做任何状态变更。

StateFormat 在当前 5 的基线上升为 6；若实施前其他批次改号，按实际下一号办理。指纹增加 Choices.RestingFill；旧格式统一拒绝，不迁移，包括空挂单存档。Restore 仍要求配置与存档口径完整相等，不能恢复后悄悄换成另一种触发模式。

## 选单与成交价

按 Book.OrderedIDs 的本地成功接收先后遍历，只考虑本根 Bar.Instrument；不能按委托ID字典序或遍历map。买单在触价模式 Low≤P、穿价模式 Low<P；卖单分别 High≥P、High>P。所有候选仍是整笔成交、价为挂单价，逐笔调用已有 Fill，保留风险103的有效请求语义、费用额度与今昨消耗规则。

P-resting-price 若取得合格同价样本，只给对应柜台、合约、连续竞价样本增加行为证据；不把触价/穿价两种建模取舍或全量成交假设升为实测。若取得反例，暂停实现并重开成交价设计；不判则不视为证据充分，继续其他独立工作。

High/Low/Close 不含 Open、盘口、成交量与真实排队信息。封板时触价即成可能过于乐观；跳空仍按挂单价，对挂单方可能保守，成交价允许落在本 Bar 的 High/Low 外，不能为了让它“像K线”而改价或裁剪。上述限制进入 Advance 和 RestingFill 导出注释及示例。

## 事务与失败

没有候选时沿用 Mark 自身的先算后提交；有候选时先 State 导出并用同一规则、日历、取整和限仓配置 Restore 成独立工作副本。依序在副本上 Fill，最后 Mark(Close)。任一步失败，丢弃副本，原模拟器不动；全部成功才以副本替换原状态。

该方式避免“先改原对象，再尝试从失败对象恢复”的二次失败。复制包括账户、手续费结算账、额度、持仓、价格、有效挂单、高水位及顺序；外部规则和日历仍按现有接口只读共享，不能把可变规则版本悄悄切换为另一份。准备副本失败时直接返回，不能先成交一笔。错误返回空 Advanced，不向调用方暴露实际未提交的部分成交；成功保留守卫的 Unchecked 与顺序 Filled 列表。

同时核验 PlaceAccepted / Restore 的基本委托字段一致性：非正挂单价、非法方向不得变成永久无法撮合的隐形挂单。只做数据形状拒绝，不补未实测柜台拒因码，不改变既有已发生成交输入 ApplyTrade 的语义。

该基础修复已独立验证并接线：TestAcceptedRequestDirection、TestRestoreRefusesInvalidOrderDirection 和 TestRestoreRefusesNonPositiveOrderPrice 均先在旧代码接受非法请求时失败，修复后通过。正对照的正常存档可以恢复；失败不留下冻结或新序号。只拒绝原本不合法的数据，未改变有效挂单语义和字段集，因此不抬当前格式5。F9c 的新口径字段仍等前置结果，尚未实施。

## 验证矩阵

| 范围 | 正向与反向判据 |
|---|---|
| 触发边界 | 买卖两侧各覆盖相等、严格穿过、完全未触及；两种口径必须给出不同的相等边界结果 |
| 顺序与隔离 | 依次 z、a 挂单，按 z、a 成交；其他合约候选即使价位可触发也不动；撤掉重挂在末尾 |
| 完整等价 | Advance 的完整 State 与同起点按相同顺序手动 Fill 再 Mark 一致；不限于成交条数或权益 |
| 中途失败 | 构造裸平额度在第一笔成交后变化，使第二笔跨今昨取整候选分歧而报错；先独立确认第一笔可成、第二笔确实失败，随后验证 Advance 原状态逐字段不变 |
| 恢复与口径 | State/Restore 后仍按序号成交；旧5格式含空簿一律拒绝；零口径空簿也拒绝且不计价；预设保持未指定 |
| 模型边界 | 买跳空/卖跳空仍挂单价；封板触价的乐观性明示；挂单有序号而非真实柜台排队位置 |
| 基本字段 | 非正价/非法方向的接受单与存档明确拒绝；正常有效请求仍可往返 |

破坏项包括删掉严格比较、买卖方向对调、按 ID 排序、误触其他合约、Fill前在原对象动状态、计价忘提交、丢失口径/版本校验和预设偷偷赋值。先检验测试能红在目标性质上，再做根模块、cmd/oracle回归与适用完整清单验证。

可行性探针已落实为 TestOrderedClosePairFailureFeasibility：合成 lh 昨2今2、额度2，先挂 z-first 一手、再挂 a-second 两手，价格14010。先手动 Fill 第一笔确实成功并改变完整状态，再 Fill 第二笔确实因 §17 决策点1 失败，且单笔失败能回到第一笔之后的状态。该探针只用现有接口，不提前实现 F9c，也不是实际柜台交易。
