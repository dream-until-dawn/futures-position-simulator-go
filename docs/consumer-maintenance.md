# 使用者接入与维护手册

核对日期：2026-11-02。适用运行代码基线：`63829d5dea6109765b01a81d06b755e7d6e0878a`。后续仅验收文档及合并的提交不改变该运行基线；发布与登记状态仍须核实际记录。本手册面向回测引擎、研究平台、账本重放工具和后续维护者，说明当前可依赖的行为及使用责任，不代表完整 v1.0 已发布。

## 1. 交付定位与适用结论

本库的主要职责是：**给定显式规则、初始状态、已知成交及计价/结算事件，计算持仓、资金、费用、冻结和跨日结果。** 当前可以交付外部成交事件驱动的离线核算与重放能力。

当前开发版本常量为 `v0.4.0`，它不是稳定发布承诺。接入应固定准确提交及依赖校验文件，不能根据版本常量推断全部功能是否存在，也不能用浮动 `main` 作为可复现实验标识。

| 使用需求 | 当前适用性 | 使用条件 |
|---|---|---|
| 策略引擎已决定成交，需核算账户与今昨仓 | 可接入 | 提供完整成交、规则和明确口径；处理所有错误 |
| 外部事件流重放、逐日结算、差异定位 | 可接入 | 明确事件顺序、初始存档、规则版本及交易日历 |
| 模拟挂单冻结与撤单、由引擎决定何时成交 | 有限制可接入 | 当前手动 Fill 只能按挂单价全量成交 |
| 输入 K 线，自动得到经现场验证的挂单成交 | 当前不具备 | F9c 尚未交付；Advance 只做守卫与计价 |
| 还原真实盘口、队列、部分成交、滑点与强平执行 | 不适用 | 这些不在当前模型能力内 |
| 将本库直接作为实盘交易网关 | 不适用 | CTP/oracle 是独立取证工具，不是通用交易执行服务 |

本手册中的“已实现”表示准确代码中存在且有相应测试。“有观测”表示特定环境、样本和字段具有证据。“规则成立”必须另看样本是否足以排除其他解释。三者不得互相替代。

本手册按上述基线汇总当前契约；设计文档或README中带日期的旧横幅保留历史语境。出现冲突时先核对应提交的实际导出代码与原始证据，不凭文档更新时间覆盖历史观测，也不将“支持六所规则结构”理解为六所全部品种均已现场验证。

## 2. 模块分工与使用者责任

| 层次 | 主要模块/入口 | 负责什么 | 使用者仍需负责什么 |
|---|---|---|---|
| 业务门面 | 根包 futsim / Simulator | 串联核算、挂单、计价、结算和状态 | 按账户串行调用，正确选择业务入口 |
| 持仓与账户 | position、account、pnl、view | 明细、今昨仓、盈亏和展示投影 | 成交身份、方向、初始成本与外部字段映射 |
| 费用与占用 | fee、margin | 显式费率、取整与保证金分组 | 费率生效日期、公司加收、适用账户与品种 |
| 委托与简化成交 | order、match | 校验、冻结、挂单簿、约定的即时成交 | 成交概率、价格、时间、队列及执行模型 |
| 参考资料 | refdata、refdata/live、refdata/exchange | 规格、费率、日历、快照与来源标签 | 资料真实性、完整性、时效及历史版本 |
| 显式策略 | risk、lifecycle | 阈值信号、补资、资格/期限/保证金台阶 | 阈值政策、资格资料和真实制度的适用性 |
| 重放 | replay、cmd/replay | 自包含输入、逐事件提交、计算账单、首差异 | 事件生成、数据清洗、分段连续性和实验归档 |
| 对拍与取证 | conformance、fixture、ctperr、cmd/oracle | 比较、已知差异、有限拒因语料、现场取证 | 现场授权、安全边界和独立证据解释 |

库的计算结果不会自动成为交易所、期货公司或银行认可的账单。取证工具与离线引擎应分开部署；普通回测不需要真实凭据、柜台连接或 Windows CTP DLL。

## 3. 当前能力与逐项限制

| 能力 | 当前实现 | 明确限制与误用后果 |
|---|---|---|
| 持仓 | 多空、逐笔明细、今昨仓、开平转换 | 初始状态必须独立确认；不能从单个总持仓数恢复完整成本与当日额度 |
| 盈亏 | 逐日盯市及逐笔对冲相关计算/展示；盘中计价 | 成本基线与计价口径必须明确；不同平台同名字段不一定同义 |
| 手续费 | 开仓/平昨/平今，按金额与按手数组合，盘中与结算费用记录 | 取整存在剩余未判候选；不能把通用平仓的费档直接等同于实际消耗的今昨明细 |
| 保证金 | 交易所/公司两层，显式基准价、大边及分组 | 按品种大边与按合约大边不同；公司加收为零会低估有实际加收账户的占用 |
| 账户 | 动态权益、可用资金、冻结、模拟出入金、风险度 | 模拟 Withdraw 不等于真实银行可出金额；非正权益风险度不可解释为0% |
| 委托 | 限价校验、冻结/解冻、接收顺序与序号高水位 | 不提供订单簿深度；不支持将部分成交当作当前 Fill 的参数 |
| 手动成交 | 外部 ApplyTrade，或已挂单 Fill | 两条路径不能对同一笔成交重复入账；Fill 的成交价不能由调用方覆盖 |
| K线推进 | Advance 的交易日/区间/时段/涨跌停守卫及 Close 计价 | Filled 当前恒为空；缺某些校验输入会记录 Unchecked，必须检查 |
| 日终结算 | 盈亏兑现、手续费结算、今转昨、基线重置、次日占用 | 不能带活跃挂单/冻结跨日；需要本日实际结算价，不能拿收盘价代填 |
| 存档恢复 | 完整内核 State、版本/口径/冻结及一致性验证 | State 不包含全部规则、日历、限仓等外部配置；不能只存 State 就宣称可复现 |
| 回放 | 显式事件、规则绑定、有效前缀、计算账单和首差异 | 不猜测成交，不自动重排/重试事件；有输入和报告资源上限 |
| 风控 | 显式三项阈值、只读风险信号、按分最小充分补资 | 不执行强平/入金；仅在其他输入固定的条件下成立 |
| 生命周期 | 显式投资者资格、持仓期限、交易期限、保证金台阶、原子跨日规则切换 | 不自动下载或认证真实交易所制度；到期阻断不会代替调用方平仓 |

范围按期货、CNY、投机路径理解。接口保留某些投保/合约字段，不代表期权、组合、套保套利优惠、多币种或实物仓单交割已实现。

## 4. 入口选择：核算、校验、冻结与成交

| 入口 | 含义 | 关键契约 |
|---|---|---|
| New(Config) | 建立账户及规则上下文 | Rules 必须存在，Choices 必须明确；生命周期日期须匹配 |
| Mark(day, quote) | 更新计价并重算相关账户结果 | HasLast/HasPreSettlement 区分缺失与数值；不是成交事件 |
| ApplyTrade(day, trade) | 将已发生的外部成交记账 | 不跑 Submit 的八项报单校验；保留核算自身的合法性检查 |
| Submit(day, at, request) | 校验后立即按报价全量成交并记账 | 不进入等待市场成交的过程；可能给策略制造现实中拿不到的成交 |
| Place(day, at, id, request) | 校验后冻结并挂单 | 不成交，后续由调用方决定 Fill 或 Cancel |
| PlaceAccepted(day, id, request) | 记录外部已经接受的挂单 | 不跑八项报单校验；仍核资金与累计可平仓量等一致性 |
| FreezeOf(day, request) | 计算该请求的冻结需求 | 不是接受委托的证明，也不等于全量报单校验通过 |
| Fill(day, id) | 对该挂单全量成交、价格等于挂单价 | 只能决定何时调用；不能通过此 API 实现任意成交价/部分成交 |
| Cancel(day, id) | 撤掉本地挂单并释放其冻结 | 只影响本地账本，不向真实柜台撤单；未知编号报错 |
| Advance(bar) | K线守卫后按 Close 计价 | 不触发挂单撮合；处理 Unchecked 后才能判数据已查齐 |
| State / Restore | 导出/校验恢复内核状态 | 带上对应外部 Config；不要用缺字段 JSON 或手工拼状态绕过一致性 |

**接入选择建议：**

1. 外部引擎已经产生完整成交记录，使用 ApplyTrade，并在外部维护成交去重及订单生命周期。match.Trade 没有成交唯一ID，直接 API 不提供全局幂等。
2. 需要检验下单并模拟占用时，使用 Place → Fill/Cancel，接受当前“挂单价、一次全量”的明确假设。
3. 需要真实部分成交或与挂单价不同的成交价，同时还要维护对应剩余冻结时，当前门面没有一条完整的部分成交更新入口。不能保留原挂单冻结又额外 ApplyTrade，并假称订单生命周期已一致；需先设计适配并核全状态。
4. Submit 适用于明确选择即时全量成交假设的实验。价格维度可能买贵/卖便宜，成交概率维度却过于乐观，不能统称“保守模型”。

拒单、没查成、已接受、已成交必须是不同状态。错误字符串不作为稳定协议字段；有限类型、明确返回值和调用上下文优先。ctperr 查码的 known=false 表示没有观测，不能把零码作为真实拒因。

## 5. 必须绑定的输入与口径

| 输入 | 最低要求 | 不可采用的替代 |
|---|---|---|
| 合约身份 | Exchange、Product、四位 Year、Month、乘数、tick、今昨属性等 | 仅用连续合约代码或含歧义的简写恢复具体交割月 |
| 初始账户/持仓 | 日期、结存、完整明细/基线及完整存档中的额度/挂单/序号 | 由末端资金或总持仓倒推唯一历史 |
| 价格 | 最新价、昨结算、本日结算及各自存在性/时间/来源 | 缺失填0，或将收盘、最新、昨结算互相代用 |
| 费率 | 开/平昨/平今六项费率、有效区间、账户适用范围 | 只取交易所公告就断言已包含公司加收、返佣或特殊费用 |
| 保证金 | 多空按额/按手、公司加收、MaxMarginSide及分组口径 | 以零加收的演示配置代表所有账户 |
| 日历 | 有序交易日、时段、夜盘覆盖、按所停盘信息 | 按工作日推交易日，或用交易日拼出夜盘的自然日期 |
| 下单校验输入 | 限仓、涨跌幅/昨结算、取整方向、资金/可平量及状态事实 | 缺资料当“无限额/已通过” |
| 生命周期 | 完整期间、投资者资格、合约期限及保证金台阶 | 默认所有自然人可持至最后交易日 |

Choices 的八个字段必须逐一审阅：FeeBasis、FeeRounding、MarginBasis、SideScope、Mark、Algorithm、FreezeMargin、UndatedCloseOnUseHistory。前七项的零值是未指定；最后一项零值允许开户，但在相关 UseHistory 裸 CLOSE 路径上拒绝猜测。

CTPChoices() 会有意留下 FeeRounding 未指定；KQChoices() 还会留下 SideScope 未指定。预设不是可直接宣称覆盖完整真实制度的默认配置。调用方补值时，应在自己的实验清单记录选择理由、证据和敏感性结果，不能静默替库选择。

使用十进制输入与字符串序列化，避免先经 float64 再转 decimal。decimal 不自动证明业务选价和取整正确；进程级小数设置、依赖版本也应固定，不应在并行回测中随意修改全局设置。

## 6. 时间、计价、结算与生命周期

内核按显式 TradingDay 运作，跨交易日前先完成结算；自然时间与交易日分别保存。夜盘可能属于下一交易日，周末和节假日前后的跨度不能用“日期加一”推断。

Bar 按 [Start, End) 右开解释，Low 必须为正且 Low ≤ Close ≤ High。有日历时要求整根位于同一个连续时段，跨休息段的大K线应由上游拆分或明确采用其他输入方式。未给日历时，部分时段检查不会执行；未查齐涨跌停时，Advance 可返回成功并附 Unchecked。成功返回不等于所有市场事实均已验证。

普通 Settle(day, prices, nextDay) 要求 nextDay 是有效且晚于当前日的日期；它本身不保证是日历的严格下一交易日。replay 路径额外核对所附日历中的严格下一日。直接使用门面的调用方也应做该项校验。

日终流程：

1. 处理当日挂单并核无剩余冻结。库不会根据“收盘应撤单”自动撤掉本地挂单。
2. 查齐每个非空持仓合约的本日结算价。缺失则停止，不能用收盘价或昨结算价补位。
3. 结算兑现盈亏及结算费用，今仓转昨仓、更新成本/计价基线，清理相应日内累计与额度。
4. 绑定显式生命周期规则时，使用 SettleWithRules 提供完整次日日规则；旧规则不能跨日沿用，资格不能在切换时随意改变。
5. 次日有超期限持仓时拒绝切换，不自动平仓。调用方需在自己的模拟流程中先处理退出，再重新形成合法事件序列。

不要把 Commission 等累计字段在结算时归零解释为负手续费收入。重放账单属于本库计算账单，不是原始柜台账单。

## 7. 账户、风险和保证金结果如何解释

动态权益 Balance 的基本关系为：上日结存 + 入金 − 出金 + 平仓盈亏 + 持仓盈亏 − 盘中手续费。静态权益不含平仓和持仓盈亏；这些名字与外部系统字段映射时应逐项核定义。

Available 从动态权益扣除公司保证金、冻结保证金、冻结资金、冻结手续费，并按 Algorithm 排除不能用于可用资金的浮盈。它不等于银行真实可出金额。保证金/权益比仅在权益为正时有意义；应检查 HasRiskRatio，不能把缺失渲染成0%。

MarginGroups 是最近一次计价计算的分组结果。按品种分组时一组可能跨月份，不能把该组的方向金额直接标成某一合约的 margin_long/margin_short。

AssessRisk 使用调用方明确提供的 MaxRiskRatio、MinEquity、MinAvailable。风险上限和最低权益须为正，最低可用允许0；恰等于阈值允许。RequiredDeposit 是固定持仓、行情、费率、冻结与政策时，使三项约束同时满足的最小分位补资，不是预测未来最坏亏损或券商正式追保额。

以 B 表示权益、M 表示公司保证金、A 表示可用、r 表示最大风险比，补资约束对应 max(0, MinEquity−B, MinAvailable−A, M/r−B)，最终向上到分；实际代码对比率使用精确乘法比较并处理除法余数，不应以展示出来的四舍五入风险比替代。行情或规则变化后必须重新计算，报告不会自动入金、撤单或强平。

## 8. 存档、恢复、并发及失败语义

当前 StateFormat=5；replay 信封/报告 Format=1。两者是不同协议版本。State 的 JSON 使用 Go 字段名，小数为字符串；不要假定可通过“改 Format 数字”迁移旧档。旧格式不匹配会拒绝，不提供自动迁移承诺。

至少将下列内容作为一个可核验的实验单元保存：准确代码/依赖版本、State、普通规则快照或完整生命周期快照、Choices、日历/夜盘覆盖、涨跌停取整、限仓、原始事件顺序及其来源。State 本身保留 RulesVersion，但版本号相同不能证明外部数据内容相同，仍需绑定内容摘要。

Simulator 不并发安全。一个账户由一个有序执行器写入；多策略共享账户时先在上层确定全序。同刻事件用输入序号打破平局，不能依赖 map 遍历或 goroutine 调度。对外查询和存档也应纳入相同同步策略。

外部 Provider 和配置也应固定为本次实验的不可变输入，不应在账户运行中原地修改共享规则或映射。需要换日规则时走显式切换路径。结果确定性以相同代码、依赖、数值设置、输入内容及顺序为条件，不承诺跨任意版本自动一致。

| 失败类别 | 当前行为 | 维护动作 |
|---|---|---|
| 规则/日期/数据/前置不足 | 相应入口拒绝；某些可跳过校验通过 Unchecked 显示 | 修输入或标记该实验不完整，不补默认零 |
| 正常业务拒绝 | 按具体 API 的事务契约保持或恢复状态 | 保留错误、输入和前置状态，避免无限重试 |
| 写入或逆操作失败导致 broken | 模拟器失效；后续业务操作拒绝，State 不允许导出洗掉失效 | 停止实例，从最后可信快照和事件重新构建 |
| replay 中一个事件失败 | 仅保留已成功提交前缀，失败事件不提交 | 同时检查 error、Status、FailedIndex，不能把前缀当完整回测 |
| 外部柜台超时/未知 | 不代表接受、拒绝或没有成交 | 与离线失败区分，不能直接重连重发有副作用操作 |

不能对全部门面错误一概承诺“实例肯定完整回滚”。核心采用预计算/副本及失败失效机制，replay 在恢复副本上执行后提交的事务边界更强。发生异常后即便 Account() 仍能读到字段，也不能据此认定 broken 实例可继续使用。

## 9. 自包含回放与资源边界

推荐经 replay.Encode / Decode 生成和读取规范包，而不是手写混合大小写 JSON。Payload.Rules 与 Payload.Lifecycle 恰选其一；Initial 可为空表示新开户。生命周期 settle 需要 settlement.next_rules，不能只提供普通规则快照代替完整日规则。

事件按输入顺序，ID 在该回放内唯一；支持 mark、trade、accept、fill、cancel、deposit、withdraw、settle、risk。kind 与负载必须对应，不能把 accept 当作已跑 Submit 校验。唯一ID检查仅限该回放，不是跨文件/跨账户幂等服务。

| 项目 | 当前限制/语义 |
|---|---|
| 输入大小 | 最多16 MiB |
| 事件数 | 每次最多4096 |
| 报告大小 | 最多64 MiB；保留逐事件完整状态，不能按原始tick数估算报告大小 |
| 金额输入 | 十进制定点字符串，最多24位整数/12位小数；不接受JSON浮点数或指数表示 |
| 解码 | 拒绝未知/重复键、尾随第二文档、超深结构及不合法 null；具体可选负载按协议校验 |
| placeholder | 默认拒绝，演示必须显式允许；允许不改变来源等级 |
| 失败输出 | Run 可返回 failed 报告和有效前缀；初始化失败时相关状态可以为 null |
| 摘要 | PayloadSHA256 绑定规范解释后的输入，不是外部来源签名或真实性认证 |
| 文件发布 | 输出必须不存在；同目录临时写入、同步、无覆盖发布，不承诺目录项断电持久化 |

发布后若仅临时文件清理失败，会报告已发布相关错误；此时先核目标文件，不能自动覆盖重跑。报告内部一致性校验不能替代拿原包重新执行。

高频/长历史回测应分段保存并校验边界：上一段 Final、下一段 Initial、同一外部规则内容/切换、未结束委托、日内额度与序号高水位。事件ID在分段间由上层去重。分段不要抹掉同日累计手续费和额度；没有依据时不能按每天新开户处理。

当前没有通用吞吐、延迟或内存SLA。已有性能数据是特定合成输入和机器下的样本，不能作为生产容量承诺；大量持仓/挂单及逐事件完整存档的开销需在使用者真实规模上测量。性能基线和复现入口见开发手册。

## 10. 置信度：如何使用测试与市场证据

本项目没有可辩护的统一“准确率百分比”。以下是本手册用于选型的定性判断，不是统计概率，也不是 refdata.Evidence 新增枚举。

| 维度 | 较强支持意味着什么 | 不能证明什么 |
|---|---|---|
| 实现可靠性 | 正反例、边界、故障注入、fuzz、race及破坏测试约束了所声明行为 | 未覆盖输入必然正确；真实市场采用相同制度 |
| 市场一致性 | 已知环境中有触发该字段且能分开候选的观测 | 所有经纪商、账户、日期、合约都相同 |
| 输入可信度 | 调用方保留日期、原始资料、适用范围与摘要，可审计来源 | 一份有 SHA 的输入就是真实且完整的制度 |

| 能力/结论 | 实现层支持 | 市场层支持与建议 |
|---|---|---|
| 确定性核算、状态恢复、回放事务 | 较强：合成手算、旧缺陷先红及完整破坏等证据 | 条件性：依赖选择的规则与口径；适合外部成交驱动研究 |
| 今昨仓、基线、冻结、盈亏等已有对拍行为 | 已有实现和夹具回归 | 有限实测：具体来源/字段/品种以规则表与夹具为准，不能整体升格为全市场 |
| 已知 CTP 与快期口径差 | 有明确 Choices 与相关反例 | 两者不能互换预设；实测差异用于约束范围，不代表任选一个都真实 |
| 风控补资、生命周期规则计算 | 较强的合成性质与失败原子性支持 | 政策输入层面：算法正确不等于参数是券商制度；需使用者确认 |
| Submit/Fill 即时或手动全量成交 | 对约定行为有测试 | 建模假设：没有排队/流动性真实性保证，不能用于成交概率结论 |
| F9c 自动挂单成交价格 | 尚未交付 | 缺合格现场样本，不应依赖 |
| 六项剩余规则 | 部分已有事实，整条尚未收敛 | 未判定部分应拒绝外推或在实验中显式标为假设 |
| 最新只读入口与现场稳定性 | 离线错误传播/留证已验证 | 本日轮在连接前停止，无新握手样本，不能证明偶发超时根治 |

快照线格式现有四档 Evidence 为 placeholder、documented、measured-kq、measured-ctp。它们分别表示占位、文档、快期模拟观测、CTP柜台观测；标签跟随数据，不能在复制或保存时升级。measured-ctp 也不是跨账户跨时期通用认证，更不等于真实资金账户已验真。

同一来源有很多次重复观测，不等于多个独立来源。多个候选在某个样本上数值相同，也不算排除歧义。代码不会验证人为填写的标签与原始资料是否真实相符。

## 11. 已知不足及对策略结论的影响

| 不足 | 可能影响 | 使用者应做什么 |
|---|---|---|
| 无真实队列、成交概率、部分成交和滑点模型 | 高频/抢价/低流动性策略收益及容量被高估 | 外部建模并独立校准；明确当前挂单路径能力限制 |
| 手续费取整剩余候选未完全区分 | 高频小额费、长时间累计净值产生偏差 | 固定口径并做候选敏感性比较，不把差分归因于策略 |
| 公司加收资料不足 | 保证金占用偏低，可开仓量偏高 | 输入适用账户真实加收；缺失时声明实验边界 |
| 日历/费率/期限由外部给定 | 历史回测可能使用当日不可知资料，或发生错误跨日 | 保存按时点可得的历史快照，避免前视与修订后覆盖 |
| 数据质量不由核心全面认证 | 陈旧行情或缺价仍可能按错误经济含义入账 | 上游核新鲜度、时间戳、异常价、停牌/停盘与换月映射 |
| 不执行强平 | 无法据资金曲线得出真实爆仓过程和损失 | 明确另建政策；风险信号不是已经实施减仓 |
| 拒因码只覆盖已观测语料 | 把未知码或其他交易所同名原因错归类 | 保留码空间和 known 状态，不根据文本猜测 |
| 无稳定接口/存档迁移承诺 | 升级后输入/状态不兼容，旧研究无法重现 | 固定提交，平行回放比较，保留旧环境和原始输入 |
| 现场探针仍有准入/握手障碍 | 无法取得后续市场判别样本 | 不阻塞纯离线核算，但不能提前宣称完整市场验证 |

未收敛的六项真实规则：5 手续费取整、6 拒因码覆盖、7 快期昨仓字段语义、12 实际出金、14 非零公司加收、19 声明与实际行为常数项。各项内部有部分已判明事实，不表示这些领域全部未实现，也不表示可以忽略未判部分。细节与取证条件见 [交付门槛](./delivery-gates.md) 和 [规则调研](./cn-futures-rules.md)。

期权/组合、套保套利优惠、多币种、实物交割、返佣、强平执行、盘口深度及跨会话自动重发保持排除边界。显式输入期限和保证金台阶不等于已覆盖交割过程。

## 12. 使用者接入与验收步骤

1. 固定源码提交与 Go/依赖版本，按提交读取本手册及原始验收证书。不要把当前测试总数当作未来提交的承诺。
2. 选择输入路径：已知成交记账，或明确的挂单价全量成交假设；记录策略层负责的成交与风控政策。
3. 建立合约、费率、保证金、日历、限仓、Choices 的版本化输入，保留生效日期、证据等级与来源。没有历史完整资料时降低研究结论范围。
4. 使用独立模块示例跑通，再替换自己的数据；placeholder 的显式许可只用于合成演示。
5. 先用可手算小样本验证多空、今昨、两档平仓费不同、费率两加项均非零、公司加收非零和分组跨月场景，避免零值假通过。
6. 做拒绝/缺失反例：无结算价、错交易日、缺规则覆盖、累计超平、未知口径、重复事件、被篡改存档及过期日规则都应按契约失败。
7. 至少跨两个交易日核结存链条、今转昨、手续费重置、额度与挂单处理；并行比较不同时点存档恢复后结果。
8. 固定外部相同样本，分别对拍账户字段、持仓明细及计算账单。字段“同值但未触发”单独列出，不算已验通过。
9. 运行小规模策略，再做极端行情、费用/加收/成交假设敏感性分析。比较原始小数，不只比较格式化显示值。
10. 仅在边界已被自己的回测业务接受后扩大规模；记录仍依赖模型假设的收益、容量和风险指标。

一个建议的接入验收记录应包含：数据/规则摘要、时间范围、准确版本、已覆盖入口、手算预期与实际值、失败反例、未查项、已知差异、未触发字段以及批准使用该假设的人或流程。

## 13. 可复现示例与命令

以下只执行离线示例，不需要 .env 或柜台。主模块声明 Go 1.22；本项目当前验收工具链固定 Go 1.27.3、GOEXPERIMENT=nojsonv2。最低 go.mod 声明不能替代最低版本兼容性矩阵的实测。复现验收时采用固定工具链及该编译选择，尤其不要静默更换 JSON 后端。

在仓库根目录执行（输出目录必须全新且不存在同名输出文件）：

```powershell
$env:GOEXPERIMENT = 'nojsonv2'
$env:PYTHONUTF8 = '1'
New-Item -ItemType Directory -Path offline-results/consumer-demo
go build -o offline-results/consumer-demo/replay.exe ./cmd/replay
./offline-results/consumer-demo/replay.exe demo -out offline-results/consumer-demo/bundle.json
./offline-results/consumer-demo/replay.exe run -bundle offline-results/consumer-demo/bundle.json -allow-placeholder -out offline-results/consumer-demo/report.json
./offline-results/consumer-demo/replay.exe diff -left offline-results/consumer-demo/report.json -right offline-results/consumer-demo/report.json -out offline-results/consumer-demo/diff.json
```

合成 demo 为25个事件、两次结算，最终结存1000000，仍有一手昨仓，并非已经全部平仓。命令中的 allow-placeholder 是对演示数据的显式许可，真实接入不能照抄为默认许可。再次演示请换全新目录，不覆盖旧证据。

直接执行 replay 二进制：diff 相同为退出0、差异为2、错误为1。go run 包装器不会原样传递全部非零码，自动化应构建后直接执行。

在 examples/offline-replay 目录执行：

```powershell
go test ./... -count=1
go run . -scenario replay
go run . -scenario lifecycle
go run . -scenario frozen
go run . -scenario lifecycle -invalid
go run . -scenario frozen -invalid
```

最后两条应非零退出。lifecycle 正例次日结存1099、公司保证金253、RequiredDeposit=166、规则版本3；frozen 正例两笔订单、序号高水位19。全部数据为合成，不能将这些数值用作真实合约参数。示例含自己的 go.mod 和本地 replace；真正外部工程应按已选准确提交引入，按自身包管理方式固定依赖。
