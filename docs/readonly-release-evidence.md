# 只读发布证据与现场准入分期设计

## 1 已观察事实与本批目标

自然日2026-11-02夜盘登记准备在21:09的remote-git阶段失败：唯一git ls-remote命令退出128，原始输出明确为连接github.com:443时SSL_ERROR_SYSCALL。完整异常链、命令原始字节及哈希已私有留存。没有最终ready、实际启动层或柜台启动目录，没有读取.env、连接柜台或报撤单。原明早跟进11-03已经删除，不恢复，不重跑这一失败轮。该证据只定位本次Git传输错误，不解释历史柜台结算确认超时。

问题在于将即时GitHub连通性与柜台单次连接绑定。修订为两个明确阶段：发布登记先单次核实真实远端；执行阶段只读取绑定准确发布和明确时窗的短期封存凭据。执行时没有实时Git网络请求，也没有网络失败后的缓存回退。不能把本轮失败记录补写为成功，不能为赶夜盘省略完整验证。

## 2 发布阶段与冻结边界

新增scripts/readonly_admission/release.py，独立完成固定GitHub仓库的origin URL核对、main/dev真实远端提交核对及排他落盘。调用沿用有界命令、私有原始输出和失败阶段；每条命令只尝试一次，TLS继续开启。失败不生成可用发布凭据，写入、fsync、读回失败均向上传播。

凭据格式固定，包含版本、有限用途simnow-params-readonly、准确source/main、登记plan哈希、固定origin、main/dev两refs、明确北京时间起止和真实完成核验时间。配置同时封存凭据路径及SHA256。有效期从真实核验结束至窗口结束最多30分钟，核验完成不得晚于窗口开始；窗口必须正向且不超过5分钟。缺键、额外键、重复JSON键、非整数版本、时区不合格、未来时间、过期、内容/用途/源码/远端/计划/时窗不匹配均拒绝。不得通过CLI切换到旧逻辑或放宽有效期。

发布阶段新鲜核验不替代准确源码完整测试、准确源码/文档/main/dev的真实双平台CI和清洁工作区。生成凭据时仍须成功访问固定远端；失败只能停止该登记，不把Git API成功或本地tracking refs充当ls-remote成功。凭据可提前完成一次，后续执行不要求GitHub持续在线。

## 3 执行阶段与能力边界

Checks.steps保留完整发布审计含remote-git；新增execution_steps明确以release阶段校验封存凭据代替该网络步骤。run_registered只使用execution_steps，固定只读argv、进程身份、源码清洁/本地refs、构建/DLL/证书/全部原始证据、真实时窗、唯一启动与.env共享锁全部保留，缺发布凭据不得退回实时Git或跳过检查。真实执行阶段仍会进行本地git只读命令，但不执行fetch/ls-remote/网络CI查询。

执行语义是“已封存发布所绑定的本地源码与构建符合登记”，不承诺封存后远端分支永不前移。执行前远端变更在本地未知的短暂可能性是明确边界；本地任何漂移仍拒绝。本批限认证/登录/结算确认/经纪商参数查询，不能扩展为一手交易的发布策略。柜台通路仍由唯一新鲜握手判断，失败即停、不重连重试、不另开连接补证据。
