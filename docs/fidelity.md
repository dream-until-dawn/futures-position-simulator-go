# 适用边界与保真度

「近乎 100% 模拟中国期货市场」这句话，只在明确的条件下成立。本文说清楚那些条件是什么、
已经验证到什么程度、哪些地方是取舍、哪些地方还没有证据。

读这一份，是为了判断**你的策略结果能不能信**。

> **当前状态：文档阶段，尚无实现。通路已实测，规则未实测。**
> 本文现在写的是**将要成立的条件**与**将要验证的方式**，不是已经达成的结论。
> 每个版本推进后回来改这一份，把「计划」逐条换成带日期与原始数据的「已验证」。
> 在那之前，本文最重要的一节是第 4 节：**未验证的**。

---

## 一句话结论

**本库还原的是「记账与结算」，不是「成交」，也不是「风控执行」。**

给定一笔成交、一根 K 线、或一个交易日的结算价，持仓与资金会变成什么样——
这一部分在下列条件内力求与真实柜台**逐字段一致**。

成交本身如何发生——排队、部分成交、滑点——取决于回测引擎喂进来什么，本库**不建模**。

强平在什么时候、以什么顺序、平多少——那是**期货公司的风控制度**，各家不同、含人工环节，
本库**只给判据，不给执行**。这一条是中国期货特有的，展开在第 3 节。

---

## 1. 成立的前提

### 账户与合约

| 项 | v1.0 覆盖 |
|---|---|
| 交易所 | 上期所 / 上期能源 / 大商所 / 郑商所 / 中金所 / 广期所 |
| 品种类别 | **仅期货**。期权、组合、即期不在覆盖内 |
| 投机套保标志 | **仅投机**。套保与套利的保证金优惠不建模（字段保留） |
| 持仓方式 | 综合持仓（可双向）与净持仓，均可 |
| 今昨仓 | 区分与不区分两条链路，按合约的规则数据决定 |
| 币种 | **仅 CNY** |

### 规则数据必须与所模拟的环境一致

⚠️ **模拟环境的规则数据与生产不同。** 保证金率、手续费率、涨跌停幅度在模拟盘上
往往是简化或过期的值。用错环境，每个依赖费率或保证金率的计算都会偏，
而偏差看起来像模拟器自身的缺陷。

- 回测真实历史 → 用与该历史时点匹配的**固定快照**
- 对拍模拟环境 → 从同一环境取规则数据

⚠️ **保证金率与手续费率会被交易所随时调整**（节假日前、行情异动后、品种活跃度变化时）。
一份快照只对应一个时点。回测跨越调整日而不换快照，结果与真实账户必然不同——
这不是缺陷，是输入不同。**本库不隐藏这一点，`Version` 恒定且可查。**

### 引擎必须提供的输入

本库不产生行情，缺什么就退化什么。**退化的方式都是显式的**，不会拿一个价格顶替另一个：

| 输入 | 不提供时 |
|---|---|
| **结算价** | ⚠️ **必给，缺它 `Settle` 直接报错；收到 `0` 也报错**（没有任何品种的结算价会是零，`0` 只可能是缺失的伪装）。⚠️ 免费日线源上**中金所品种 98.6% 缺失且延续至今**，须改用中金所官网，见 [design.md](./design.md) §6.5 |
| **昨结算价** | 首日必给（作为基线）。之后由上一日的 `Settle` 自动推进 |
| 最新价 | 浮动盈亏与盘中风险度无从计算，相关字段为零并给出原因 |
| 涨跌停价 | 报单的涨跌停校验**跳过并给出原因**，不拿别的价推算 |
| 交易日历 | ⚠️ **必给。** 不用工作日近似，理由见下 |

⚠️ **交易日历不可用工作日近似。** 夜盘属于下一个交易日，一个交易日可以横跨三个自然日；
长假前后的交易日映射必须查日历。用工作日推会在每个长假前后错一次，
而那正是保证金上调、风险最高的时候。

## 2. 将要验证到什么程度

### 全字段对拍（最强的一条）

`cmd/oracle conformance` 把本库的输出与真值**逐字段**比对：
**每个字段落进三档之一，三档之外判失败：**

| 档 | 含义 | 算不算通过 |
|---|---|---|
| 一致 | 值对得上，**且本次样本内被触发过** | ✅ 唯一算通过的一档 |
| 不建模 | 已在 `policy.go` 声明，**且带到期版本** `NotModeledUntil` | ✅ |
| **未触发** | 值对得上，但本次样本内**从未被触发** | ⚠️ **不算**，单独计数 |

### ⚠️ 第三档：零值假通过

**一个字段在两边都是零、且本次样本从未触发它，对拍照样判「一致」。**

这不是假想。本仓库第一次连上快期模拟时，账户是空仓，`balance` 与 `ctp_balance`
都是 `1000000.0`——两个口径「完全一致」。而这恰恰**什么都没证明**：
空仓时任何两种权益口径都相等。

一般化之后它吃掉一大片字段：`close_profit`、`commission`、`volume_long_his`
这些只在特定动作后才非零的字段，只要对拍样本没真的开仓、结算、平仓走一遍，
就会**以零值静默通过**。

这与「阴性结果不能当阳性用」是同一件事，也与「对拍测试零次迭代也会绿」
是同一条原理——只是层级从「测试跑了几次」抬到了「**字段被触发过几次**」。

**触发判据**（从简）：该字段在本次样本内出现过非零值，或出现过变化。

**门槛**：v0.2.0 允许若干未触发字段（列白名单并说明何时能触发），
**v0.8.0 必须为 0**。

两个真值来源，角色不同（详见 [design.md](./design.md) §5）：

| 口子 | 覆盖 | 为什么需要它 |
|---|---|---|
| 天勤快期模拟 | 账户与持仓的**全部**字段 + 报单 + 成交（数量见 [state.md](./state.md)） | 纯 Go 可达、7×24、原生区分两个成本基线 |
| SimNow（CTP） | 两套平仓盈亏口径、6 个手续费率、4 个保证金率、今昨仓与大边开关 | 天勤给不了这些；且它是**裁决天勤与真实柜台口径差**的唯一途径 |

> **挑着比永远发现不了「有个字段我压根没建模」。**
> 参照项目在补上全字段对拍的当天就暴露出 35 处差异与 4 个从未建模的字段。

### 结算单对拍（中国期货特有，也是最有力的一条）

结算单是逐日盯市的**最终陈述**：期初结存、当日盈亏（平仓盈亏 + 持仓盈亏）、手续费、
期末结存、保证金占用、风险度全在一张表上互相勾稽。

它对上了，说明整条日终链路是对的——而日终链路正是本库与加密货币模拟器分歧最大的地方。

### ⚠️ 对拍测试零次迭代必须判失败

夹具被清空或字段改名导致反序列化成空，循环一次不执行，测试照样绿——
而**一条真实数据都没核对**。这是参照项目踩过的坑。本项目从第一个对拍测试就带上
迭代次数断言。**永远绿的测试等于没有测试。**

## 3. 明确的建模取舍

### 不建模盘口深度

没有逐笔委托数据就无从建模排队、部分成交与滑点。硬造只会给出**看似精确实则杜撰**的结果。
内置撮合的假设是：K 线驱动、无深度、全成或不成。

有自己撮合逻辑的引擎可以绕开内置撮合直接灌成交，这条路径永远保持完整可用。

### ⚠️ 不建模强平的执行 —— 这一条最重要

OKX 那类交易所的强平是**交易所的确定性算法**：输入相同则输出相同，可以被 100% 复现。

中国期货**不是**：

```
风险度 ≥ 100% → 期货公司发追保通知 → 客户在规定时间内补足或自行减仓 → 未补足 → 期货公司强平
```

「规定时间」「先平哪个合约」「一次平多少」「用什么价挂单」**全部由期货公司的风控制度决定，
各家不同，且含人工环节**。CTP 的平仓标志里同时有「交易所强平」「强减」「本地强平」三种，
正说明它不是单一算法。

**本库因此：**

- 给**判据**：风险度、可用资金是否为负、是否触发追保线
- 不给**执行**：输出信号与风险敞口，由使用者按自己的风控制度处理
- 提供一个**可选**的约定策略，显式标注为**约定而非还原**，**默认关闭**

⚠️ **这意味着：任何依赖「爆仓时刻的确切损失」的策略结论，本库给不了确定答案。**
它能给的是「什么时候会被通知补钱」，这一条是确定的。

### 一根 K 线只给区间，不给路径

高低点的先后顺序不可知。触发类判定（涨跌停、条件单）在一根 K 线内的顺序是**约定**，
不是还原。日线级别的回测尤其要注意：一根日线内价格可能先触涨停再跌回。

### 精度

一切金额与价格用 `shopspring/decimal`，不用 `float64`。中国期货的结存要**逐日累加**，
浮点误差会随交易日数线性积累。

⚠️ 但真值来源本身可能是浮点：天勤 DIFF 的 JSON 数值是 float64
（文档示例里就有 `9963216.550000003` 这样的值）。因此对拍时**精度类差异单独计数**，
不并进「一致」——为的是让它的规模一直看得见：哪天从 `1e-14` 变成 `1e-6`，
说明出了别的问题。

## 4. 未验证的（当前最长的一节）

**通路已实测，规则一条都还没实测。** cn-futures-rules.md 里的规则全部是「文档」或
「待实测」等级。⚠️ 这两件事很容易被混为一谈：**能连上柜台，和从柜台上问出正确答案，
中间隔着六个实验。**

> **2026-09-07 更新**：两条对拍通路都已跑通并登录成功（[probes.md](./probes.md) §6），
> 所以下面这些不再是「不知道能不能验」，而是「还没验」。区别很大——
> 前者是风险，后者只是工作量。

### 待实测的规则（条数见 [state.md](./state.md)）

见 [cn-futures-rules.md](./cn-futures-rules.md) §13 与 [roadmap.md](./roadmap.md) 的实验清单。
它们的影响面：

| # | 问题 | 若猜错会怎样 |
|---|---|---|
| 1 | 盘中保证金用哪个价 | ⚠️ 可用资金曲线整体错位 → **追保时点错** → 整个风控链路的结论不可信 |
| 2 | 盘中持仓盈亏用哪个价 | 风险度错，方向不定 |
| 3 | 单向大边按品种还是按合约 | ⚠️ 跨期套利的保证金**可能差一倍**。单合约样本上两种解释同值，测不出来 |
| 4 | `NoUseHistory` 合约的平仓消耗顺序 | ⚠️ **不止手续费**：平仓盈亏的基线一并改变（平昨用昨结算价 / 平今用开仓价），当日盈亏与结存跟着错。日内策略被系统性高估或低估 |
| 5 | 手续费的取整口径 | 单笔差几厘，逐日累加进结存，长周期漂移 |
| 6 | 报单被拒的错误码 | 使用者的错误处理分支接不住 |

⚠️ **第 1 条与第 3 条是最危险的**：它们的错误不会让任何数字看起来不合理，
只会让某些参数组合在扫描结果里被静默淘汰或保留。

### 两个真值来源之间的差异，本身未测量

⚠️ **快期模拟是天勤自己的模拟撮合与结算，不是 CTP 柜台。**
「与快期模拟一致」不等于「与真实账户一致」，而这两者之间差多少，**现在完全不知道**。

在 v0.8.0 用 SimNow 交叉验之前，任何基于快期模拟的对拍结果都要读作
「与快期模拟一致」，不能读作「与真实柜台一致」。本库的文档会一直这样措辞。

### 数据源的缺口

- **DCE 日行情端点未打通**（412，见 [probes.md](./probes.md) §2）。
  结算价需另找路径或由使用者提供。**不会拿别家数据顶替，也不会插值**
- SimNow 尚未注册，能否登录、7×24 环境是否可用**完全未验证**

## 5. 明确不覆盖

| 项 | 为什么 |
|---|---|
| 期权 | 保证金模型完全不同，值得单独一个大版本 |
| 组合保证金 / 套利组合 | 需要交易所的组合定义与审批数据，回测拿不到 |
| 套保 / 套利的保证金优惠 | 需要套保额度审批数据 |
| 多币种账户 | 国内绝大多数账户只有 CNY |
| 实物交割的仓单流转 | 个人客户不进交割月 |
| 连续涨跌停的扩板与临时保证金上调 | 是交易所的临时公告，非公式。可由使用者通过规则数据注入 |
| 银期转账与出入金到账时点 | 与交易核算无关 |
| 强平的执行 | 见第 3 节 |

## 6. 自己验一遍

本文的任何说法都不该被直接相信。等实现落地后，验证路径会是：

```bash
go test ./...                       # 单元测试与守卫
cd cmd/oracle && go run . -h        # 嵌套模块：probe / conformance 两个子命令
```

对拍需要**你自己的**柜台账号（本仓库的凭据不入库）。配置写在 `.env`，
模板与各项取值来源见 [`.env.example`](../.env.example)，申请入口见
[probes.md](./probes.md) 的「待办」一节。

⚠️ **在 `cmd/oracle conformance` 能跑出「有差异 0、未分类 0」之前，
本文第 2 节的一切都是计划，不是结论。**
