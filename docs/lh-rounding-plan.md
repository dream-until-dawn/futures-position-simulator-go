## 目的与判据

固定比较一笔通用平仓 2 手、平今额度 1 时，结算手续费的两个候选：按笔为 RoundCent(P×M×rT + P×M×rY)，分段为 RoundCent(P×M×rT) + RoundCent(P×M×rY)，均按既有 HalfUpToCent。候选适用于每手固定费为零的按额品种；费率结构变化则停止并修改方案，不强套公式。

旧样本 P=11780、M=16、rT=0.0004、rY=0.0002，两者都是 113.09，仍是“不判”。不能据此选一种算法。新的判据只看交易日结算单该笔 Fee，盘中手续费增量只记录，不能代替结算读数。

## 工具前置修复

2026-10-23 15:30 后续设计：继续核验余下五种只读查询（Account / CommissionRate / Instrument / MarketData / BrokerParams）。旧实现以共享单元素通道或共享合约数组接收结果，排空旧通道不能隔离排空之后才到来的旧回报；部分回调也可能阻塞柜台回调线程。统一复用 queryBatch 的 RequestID、完整结束和首错保留机制，错误、超时及即时返回码均不能返回旧数据或半截成功。行情和合约保留精确合约筛选，费率增加精确合约筛选；资金与经纪商参数必须唯一，其他三类精确匹配后也必须唯一，多条匹配不擅自挑第一条。BrokerParams 同样经过查询串行节流。函数签名与非 Windows 报错桩保持不变，不改变登录和报单路径。

验证先用纯 Go 假发送器覆盖即时拒绝、回调错误、超时旧编号晚到、空/重复/错合约及正常成功；再检查 Windows 九条查询的回调和调用接线，单独记录结构检查不能代替实际 DLL 的行为验证。新增破坏项检验唯一性、匹配过滤、发送返回码和请求编号隔离。完成两模块回归、适用破坏验证和 Windows 构建；真实柜台复核只读，不使用查询修复扩大报单授权。

2026-10-23 追加查询边界设计：Positions / LiveOrders / Trades / SettlementText 的回调原先只打印柜台错误，在 isLast 到来时仍可能返回空结果或部分结果加 nil error。新增私有通用分批查询收集器，以 RequestID 关联回报，保留首个错误，错误结果不返回部分数据；超时后停用该请求，迟到数据与结束标志不得污染下一次查询；重复结束回调忽略。发送时即返回的非零 CTP 返回码也必须进入失败路径。收集器以跨平台离线测试覆盖空成功、错误加空结束、部分数据后错误、超时、旧编号迟到及新请求成功。只替换上述四类分批查询，资金/费率/行情/合约查询本批保持既有接口，后续单独核验。

源码 `cmd/oracle/closefee_quotaext.go` 当前先比较成交条数增量，再从整份列表找两手平仓。实施前应改为以柜台成交身份的稳定组合键取前后差集，校验唯一新增记录、方向、开平、合约及手数，排除同日旧两手记录与返回列表乱序的干扰。必须覆盖旧记录位于列表末尾、多条拆单、重复键、其他合约和无法识别记录等正反向测试。

现有 defer 注释称“只平今仓、昨仓种子不碰”，而风险 103 已证明两所显式平今可能改写为通用平仓。因此不能凭发出的平今标志保证保留种子；应复核 closeTodayOnly 等收尾实现，按实际持仓、成交和可平量制定退出策略，并修正误导性注释。撤单失败或查询失败不得宣布已收尾，必须记录待处置敞口并停止实验推进。

进一步核验 `cmd/oracle/closeorder.go`：closeTodayStep 已在观察到昨仓减少后停手报错，因此不是毫无检测；但它在首笔平今发出前仍不能保证保留种子。需明确这是事后检测，而非事前保护，并覆盖“昨仓被消耗、今仓仍残留”的退出与报告。

这些前置修复应作为独立代码批完成和验收；在核验前不运行现有交易命令。不得为了此实验扩大清理到无关合约或其他任务持仓。

## 两阶段流程与退出

1. 种子：批准范围内买开 1 手，确认成交与剩余挂单，跨一次有效结算，重新核多头今 0 / 昨 1 / 当日开过 0、空头 0。条件不成立则停止。
2. 实验日：买开 1 手，核今 1 / 昨 1；发唯一一笔通用平仓 2 手。阀门只在所需窗口调到批准值，结束及异常路径都恢复 1 并只读复核。
3. 确认唯一新增 2 手成交、最终今昨均 0、无活委托。使用实际成交价计算两个候选，形成第二阶段登记，推送并核远端后才读取对应结算单。
4. 分拆成交、候选同值、未完全平仓、费率变化或结算读数不匹配均不判；查询不明记“状态未知”，不得记成空仓。保留原始脱敏证据，不调整算法迎合结果。
5. 异常先撤本实验挂单，再核实际持仓；不能假定只有今仓残留，也不能假定 seed 仍在。需要超出批准范围的平仓/补仓则停止并交使用者决定，不自动重下种子。

至少跨一次结算，可能多次无判别力，不承诺固定收敛日。同一账户的 P-resting-price 不在待读结算读数的交易日执行。单一柜台单样本即使判别成功，也不直接提升为广泛实测规则。
