# 非交易日推进与验收

基线为 main dc88d6a。使用者授权依次完成五项工作，沿用自行验证后 dev → main 的流程。本批只使用合成数据和已有脱敏语料，不读取柜台凭据、不连接柜台、不执行交易；合成结果不提升交易规则的证据等级。当前进度以 [state.md](./state.md) 为准。

## 1 状态与事务性质

用独立合成规格和固定费率构造可重复的操作序列，覆盖开仓挂单、撤单、成交、平仓、计价、结算与存档恢复。每步比较未恢复实例和JSON往返恢复实例的完整State；失败必须完整状态不变；维护独立的挂单集合、成功接收序号及费用/手数计数，避免两边调用同一错误实现而自洽。固定种子回归与限时模糊测试并用，限制输入和状态规模。反向篡改存档与故意破坏守卫须被检出。

## 2 预期绿审计

逐项登记现有38项的编号、目标测试、原因、分类和后续措施：真实语料/柜台样本缺口、可离线补测的行为或守卫缺口、刻意的豁免/冗余/能力边界演示。可合成的输入只证明程序行为，不能填充真实观测。优先补算法未知值、阶段文字映射等纯离线缺口；保留原始分类和变更历史，不通过删除条目减少计数。审计覆盖检查必须同时防遗漏和重复。

## 3 跨平台验证

Windows与Linux分开执行根模块和cmd/oracle回归，禁用测试缓存；固定种子性质测试随普通回归执行，限时模糊测试及支持平台的竞态检查单独运行。提供跨平台本地入口与失败退出码。完整破坏扫描独立按需启动，逐项恢复，异常停止，保存JSON和日志；CI使用完整Git历史，检查跳过及工作区残留，报告实际平台边界。非Windows的CTP只有明确报错桩，构建通过不等于支持实盘。

## 4 探针离线演练

在现有假柜台与假时钟基础上增加拒单、提交超时、撤单失败/途中成交、查询失败、各阶段落盘失败矩阵，核验报单次数、最大敞口、终态、报告失败标志及是否允许继续。未知状态必须停止，不扩大收尾范围。形成下次实际日期登记与封存检查表；不把已失效的2026-10-23窗口改成可直接执行，也不提前实施F9c撮合。

## 5 性能与文档

用明确标注为合成的100/1000规模挂单和持仓测量State、Restore、Fill、Settle，记录Go/OS/CPU、ns/op、分配数与运行参数；不以单机一次结果宣称跨机器阈值。补充可复现命令与基线文件。提供简洁当前状态入口和开发验证手册，历史依据保留链接，禁止把历史待办当作当前状态。最终运行两模块完整回归、相关新破坏项及完整清单，验证后合并推送。
