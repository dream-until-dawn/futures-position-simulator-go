# 版本排期

范围与决策依据见 [design.md](./design.md)，规则依据见 [cn-futures-rules.md](./cn-futures-rules.md)，
可行性依据见 [probes.md](./probes.md)。

## 分支与发布约定

| 分支 | 角色 |
|---|---|
| `main` | 只接受来自 `dev` 的合并，每次合并打 `vX.Y.Z` tag，保持永远可 `go get` |
| `dev` | 默认开发分支，日常提交落这里 |
| `feat/*` `fix/*` | 仅当改动会持续多天且打断 dev 时才开，完事 squash 回 dev |

Go 库特有约束：

- **tag 必须打在 `main` 上**，严格 semver（`v0.1.0`），`go get` 只认这个
- **v1.0.0 之前 API 可自由变更**（v0 不受兼容性承诺约束）——要充分利用这个窗口把 API 打磨定型
- 一旦发布 `v2`，module path 必须加 `/v2` 后缀。**因此 v1.0.0 是一道必须谨慎跨过的门**

⚠️ 本机 `proxy.golang.org` 不可达（[probes.md](./probes.md) §1），
开发与 CI 必须 `go env -w GOPROXY=https://goproxy.cn,direct`。

## 排期原则：证据先于代码

参照项目的经验里，代价最高的缺陷都不是写错公式，而是**把一个猜测当成事实写进了代码**，
然后所有测试都在验证那个猜测。所以本项目的排期有一条硬规则：

> **每个版本先跑判别实验，再写实现。**
> 实验的原始输出存进 `testdata/`，结论写回 cn-futures-rules.md 并把证据等级
> 从「待实测」改成「实测」。**没有实测支撑的规则，代码里要有显式标注和守卫测试。**

cn-futures-rules.md §13 列出的**全部待实测项**（当前条数见 [state.md](./state.md)）都落在 v0.1.0。
在它们收敛之前，v0.2.0 的核算公式无从确定。

## 对拍的「不建模」必须带到期版本

验收规则是「每个字段要么值对得上，要么写明为什么不建模」。这条规则有个**可以被合法
绕过**的出口，v0.2.0 恰好会撞上：

账户的 `frozen_margin` / `frozen_commission` / `frozen_premium`、持仓的
`volume_*_frozen_*` 与 `order_volume_*` —— 共 11 个字段 —— 要到 v0.4.0 有了
`order` 与冻结才可能实现。于是 v0.2.0 想让对拍全绿，**唯一的路径就是把它们声明成
「不建模」**。而它们恰好是 [silent-risks.md](./silent-risks.md) 第一节第 7 条点名的那批：
报单冻结不建模 → 回测比真实账户「有钱」→ 开得出实际开不出的仓。

⚠️ **声明一旦写下去，没有任何机制逼它在 v0.4.0 被摘掉。** 一个「暂缓」会安静地
变成「永久」，而且是在测试全绿的状态下变的。

因此 `policy.go` 的每条「不建模」**必须带一个到期版本**：

```go
{Field: "frozen_margin", Reason: "报单冻结未实现", NotModeledUntil: "v0.4.0"}
{Field: "premium",       Reason: "期权权利金，v1.0 不覆盖", NotModeledUntil: "never"}
```

对拍工具跑在该版本**之后**仍见到未摘的条目，**判失败**。
把「暂缓」和「永久不建模」在制度上分开，成本是几行代码。

⚠️ **硬约束：第一条「不建模」声明与它的到期校验必须落在同一个提交里。**
不允许先有声明、后补校验——否则这条「防止暂缓变永久」的机制自己就先处在暂缓状态，
而那正是它要防的东西。

## 对拍的第二个洞：零值假通过

「不建模」的出口堵上了，还剩一个：**字段在两边都是零、且本次样本从未触发它，
对拍照样判「一致」。**

本仓库第一次连上快期模拟就撞见了它：账户空仓，`balance` 与 `ctp_balance`
都是 `1000000.0`，两个口径「完全一致」——而空仓时**任何**两种权益口径都相等，
这什么都没证明。

一般化之后它吃掉一大片：`close_profit`、`commission`、`volume_long_his` 这些
只在特定动作后才非零的字段，只要对拍样本没真的开仓、结算、平仓走一遍，
就会**以零值静默通过**。

它与「阴性结果不能当阳性用」是同一件事，也与「对拍测试零次迭代也会绿」是同一条原理
——只是层级从「测试跑了几次」抬到「**字段被触发过几次**」。

因此验收从两态改**三态**：

| 档 | 含义 | 算不算通过 |
|---|---|---|
| 一致 | 值对得上，**且本次样本内被触发过** | ✅ |
| 不建模 | 已声明且带到期版本 | ✅ |
| **未触发** | 值对得上，但从未被触发 | ⚠️ **不算**，单独计数 |

触发判据从简：该字段在本次样本内出现过非零值，或出现过变化。
v0.2.0 允许若干未触发（白名单 + 说明何时能触发），**v0.8.0 必须为 0**。

### 字段集漂移也要自己报出来

23 个账户字段是**一次**快照数出来的，字段集未必稳定。别靠定期人工再数一遍，
**把字段集本身变成对拍的一部分**：每次运行断言「收到的字段集 ⊆ 已知字段集」，
多出来的字段判**未分类**（即失败），而不是忽略。

这是参照项目那条经验的自动化版本——它那次是靠人补全字段对拍，才一次暴露出
35 处差异与 4 个从未建模的字段。让它变成常态，就不必再指望有人想起来去数。

## 两条 v0.1.0 要一并落地的机制

它们与前面两条（到期版本、三态验收）是**同一个形状**：一个事实有唯一的家，
而复述它的地方与那个家之间没有链接。前两条都靠「加一个机械断言」解决，这两条同理。

### 1. 单一状态源 + 禁语检查（治「改状态改不干净」）

项目状态只在 `docs/state.md` 一张表里断言：

```
kq_login        已实测 2026-09-07
simnow_login    已实测 2026-09-07
rules_measured  0/6
dce_daily       未打通
```

每个状态键**派生**一组禁语——该状态翻转后就不得再作为现时叙述出现的字符串
（`kq_login` 的禁语：「尚未实际登录」「待注册」「柜台账号还没有」…，完整表在 [state.md](./state.md)）。
主模块里一个只用 stdlib 的 `doc_test.go` 扫全部 `.md`：禁语只允许出现在
显式标记的历史留档里（`~~` 删除线、`> ✅` 横幅之内、`<!-- 历史留档 -->` 块内），
出现在别处就红。

守卫的守卫：断言状态表非空，且**每个「已实测」的键至少有一条禁语**。

⚠️ **但必须承认它的边界，否则它会变成一种虚假的安心。**
禁语表是**对自然语言的黑名单**——而黑名单漏一条就静默失效，这正是下面第 2 条
要拒绝黑名单的理由。中文里「尚未登录」有无穷多种说法，一条**新造的**过期表述
照样能穿过去。

所以它防的是**复发**，不是**首发**：

> 禁语从**状态翻转那次提交里被删掉的字符串**中生成，而不是靠人凭空想。
> 「这次改掉的话，以后不许再出现」——列表由真实编辑长出来，不由想象力长出来。

首次写出一句新的过期表述，仍然只能靠评审的人眼抓。**这一点要写在检查的注释里**，
免得后人以为绿了就等于没有过期陈述。

#### 另一半：减少复述面（这一半治首发）

上面四处过期陈述有个共同点：**它们全是复述。** 事实只有一个家
（`probes.md` §6/§7），另外几份文档各自用散文把它再说一遍。
禁语治的是复述**变质**，没治**复述本身**。

所以第二条机制是：**其他文档不断言状态，只指向那个家。链接不会过期，
因为它不含事实。**

⚠️ **它是白名单形状的，而且绕开了「白名单建不在措辞上」这条反驳** ——
措辞无穷，但**位置有限可枚举**：状态断言只准住在 `state.md` 与 `probes.md §7`。

两条机制**失败在不同的用例上**，这才是并用的理由：

| 过期陈述 | 禁语 | 减少复述面 |
|---|---|---|
| `probes.md` §5 那句、`cn-futures-rules.md` 两处（同批字符串复述） | ✅ 抓得到 | ✅ |
| `design.md` §7 整节「待用户提供」（不含任何现成禁语，禁语表见 [state.md](./state.md)） | ❌ 抓不到 | ✅ **那一节存在的唯一理由就是复述阻塞状态；若它当初是一条链接，就没有东西会过期** |
| 新造的措辞、新写的一节 | ❌ | ⚠️ 只在「新写的是纯状态节」时抓得到 |

**并用仍不是 100%**，但两者基于不同原理、不会一起失效——与脱敏的
「白名单 + 独立复查」是同一个理由。

#### 分工由「复述有没有就地含义」决定

完全消灭复述会付出可读性代价：`refdata` 来源表里的
「✅ 已登录，见 [probes.md](./probes.md) §6.3」若砍成光秃秃一条
「见 §6.3」，读者要跳一次才知道能不能用。所以分工是：

- **纯状态复述**（一节/一行的唯一职责就是报状态，如 `design.md` 旧 §7）
  → 删掉，换成链接。归**位置白名单**管
- **嵌在论证里的状态词**（如来源表里的 ✅ 与结论并排）
  → 保留，但它从此落在**禁语的爆炸半径**内

**当前散落面已量出来：`probes.md` 之外还有 23 处状态断言。**
v0.1.0 的任务不是清零，是把纯状态复述那部分清掉，并让剩下的全部落进禁语覆盖。
清零本身要有个数字可查，否则「减少复述面」会变成一句无法证伪的口号。

### 2. 脱敏用白名单，不用黑名单（治「夹具泄漏」）

判别实验的原始 JSON 要入 `testdata/probes/`，而 `snapshot.json` 里有账户 UUID。

| 写法 | 漏一个字段会怎样 |
|---|---|
| 黑名单（擦掉已知敏感字段） | 泄漏，**静默** |
| **白名单**（只留已知安全字段） | 该字段从夹具消失 → 对拍报「缺字段」→ **响** |

同一个疏忽，一个静默一个响。这与「字段集断言 ⊆ 已知集」是同一条原理的另一半：
那条管**多出来**的，白名单管**该去掉**的。

三条配套：

1. **脱敏在落盘之前做。** 先落原始盘再擦，原始文件已经上过磁盘、可能已进过
   git index —— 一次 `git add -A` 就够了
2. **脱敏后断言字段集恒等**：`夹具字段集 == 已知字段集 − 白名单外集合`，任何漂移直接红
3. **再加一条独立机制的复查**：断言夹具里不含 UUID 形状的串、不含 `.env` 里那几个值。
   它与白名单是**两套不同原理**，因此不会一起失效 —— 一个 bug 同时骗过两种不同
   机制要难得多

## ⚠️ 今昨仓前移带出的一条约束

今昨仓的划分与滚动前移到 v0.2.0 之后，有一件事**仍然**要等 v0.3.0：
**显式的平今 / 平昨声明**。于是在 `UseHistory` 合约上，**v0.2.0 平不掉昨仓**。

后果必须写明，否则正好掉进上面那个零值假通过的洞：

- v0.2.0 **能验**：昨仓基线出现在**持仓盈亏**里（结算后昨仓以昨结算价计）
- v0.2.0 **验不了**：**平仓盈亏**的平昨基线 —— 因为平不掉昨仓
- 因此 `close_profit` 在 v0.2.0 **只能靠平今触发**，平昨那条分支要到 v0.3.0 才有样本

这一条进 v0.2.0 的未触发白名单，到期版本 `v0.3.0`。

## v0.1.0「不下单的那一半」的四条约束

⚠️ **它不叫「只读的那一半」。** `goctp` 的登录链路里，`onLogin` 收到成功应答后
**立刻调 `ReqSettlementInfoConfirm`** —— 确认结算单是**写操作**，不是查询，
而且它在 2026-09-07 的 SimNow 探针里**已经发生过了**。

这不构成问题（模拟盘上确认结算单是常规动作，不确认根本不能交易，离下单很远），
**但标签必须准**：一个高估自身安全性的标签，正是本项目从头到尾在防的东西。
若日后被问「等点头的这段时间碰了账户什么」，两个名字给出的答案不一样。

### 1. `ctperr` 的取值一个都不许先填

roadmap 自己写着实验 6 的产出就是「`ctperr` 的取值」。先写等于把一批猜的错误码
钉进 v0.1.0 的交付物，而 v0.1.0 的验收恰恰是「全部待实测项收敛为实测」——
与「**每个版本先跑判别实验，再写实现**」正面冲突。

包骨架、文件、类型定义可以先有，**取值一个都别填**。
⚠️ 2026-09-07 已拿到**快期模拟**的拒因文案，但那不是 CTP 的数值错误码，
不能用来填 `ctperr`。

### 2. `refdata` 的品种索引：建它是因为它便宜，不是因为实验 3 有了结论

若大边按**品种**合并，`refdata` 必须能 contract → product 并枚举同品种全部合约；
若按合约，不需要。这个索引很便宜，且解析 CZCE 的三位月份本来就要它，所以**直接建**。

⚠️ **但代码注释与文档里必须写明这条理由。** 否则实验 3 真跑出「按品种」时，
这个索引会被读成「当初就验过了」——一个未经验证的假设就这样变成既成事实。

### 3. 这半边的产出同样要脱敏，从第一次写盘起

别以为不碰账户截面就没有标识信息。实测 CTP 结构体：

| 结构体 | 标识字段 |
|---|---|
| `CThostFtdcInstrumentField`（合约表） | **无**，干净 |
| `CThostFtdcInstrumentMarginRateField` | `BrokerID` `InvestorID` `InvestUnitID` |
| `CThostFtdcInstrumentCommissionRateField` | `BrokerID` `InvestorID` `InvestUnitID` |

⚠️ **费率是按投资者查的，应答里自然带着你是谁。** 白名单脱敏在这半边就要生效。

### 4. 拉到规则数据 ≠ 规则被实测

见 [cn-futures-rules.md](./cn-futures-rules.md) 表头的**双坐标证据等级**。
拉规则数据能让一大批字段升到「实测（取值）」，**而实验 3/4/5 一条都不会因此收敛**。

⚠️ **计数也是状态。** 验收行不许抄「N 条」「N 字段」，一律写「全部」并链接
[state.md](./state.md)——2026-09-07 已经因此栽过两次，两次都躲过了禁语检查，
因为**状态词至少是词，人眼会停；计数是数字，人眼扫过去根本不会停**。

## v0.1.0 的判别实验清单

这是当前唯一在跑的版本，它的核心交付物不是代码，是**证据**。
实验全部来自 cn-futures-rules.md §13（条数见 [state.md](./state.md)），每条都已写好判别方法：

| # | 问题 | 判别方法 | 阻塞什么 |
|---|---|---|---|
| 1 | 盘中保证金用哪个价 | 持仓不动，等行情走 1%，看保证金是否变；再用「今仓开仓价 ≠ 昨结算价」的一笔分开候选 1 与 2 | `margin` 包的全部公式、可用资金曲线、追保时点 |
| 2 | 盘中持仓盈亏用哪个价 | 持一手昨仓，看盈亏是否随行情变（候选 2 会恒为零） | `pnl` 包、风险度 |
| 3 | 单向大边按品种还是按合约 | **同品种两个不同月份**分别建多空，看合计是 `max(多,空)` 还是 `多+空` | `margin` 的合并范围，跨期套利可能差一倍 |
| 4 | `NoUseHistory` 合约的平仓消耗顺序 | 隔日建昨仓，次日开今仓，平掉**少于昨仓量**的手数（平满了三种顺序同值）。**同时看两个字段**：`Commission` 与 `CloseProfitByDate` —— 后者的差通常比手续费**大一个量级**，更容易把候选分开 | `fee` + **`pnl`** + **`account`**：消耗顺序换一个，平仓盈亏的基线（平昨用昨结算价 / 平今用开仓价）跟着换，当日盈亏与结存链条一并受影响 |
| 5 | 手续费的取整口径 | 构造理论值恰在半分附近的成交，看实际值 | `internal/decimalx`，长周期结存漂移 |
| 6 | 报单被拒的错误码 | 逐项触发八类校验失败 | `ctperr` 的取值 |

### 实验之间的时间依赖

⚠️ **昨仓造不出来，只能等一次结算。** 夜盘 21:00 之后属于下一个交易日，
但中间**没有结算**；真正把今仓变成昨仓的是日终结算。所以：

```
D 日   oracle probe -exp overnight-setup     建种子（此时全是今仓）
D 日日终  （交易所结算）                        今仓 → 昨仓，昨结算价 ← 今结算价
D+1 日 baseline-full / close-order / yd-vs-his
```

| 实验 | 何时能跑 | 今仓下能得到什么 |
|---|---|---|
| 6 报单拒因 | 任何时候，**不需要成交** | ✅ 已收敛（快期模拟侧） |
| 3 单向大边 | 当日，需两个同品种不同月份 | ✅ 完整 |
| 1/2 今仓版 | 当日 | ⚠️ **只能排除「连续重估」一个候选**，不得写成收敛 |
| 1b/2 完整版 | **D+1** | 反解出 position_profit 的基线；比较今昨每手保证金 |
| 4 平仓消耗顺序 | **D+1** | ⚠️ 本样本**分不开**「先平昨」与「先开先平」，需连续两日各建一次种子 |
| 7 yd vs his | **D+1** | ⚠️ 二者相等时**分不开**，需平掉一手昨仓再看 |
| 5 手续费取整 | 需 CTP | 天勤只给「每手手续费」，六个费率要 SimNow |

**实验 1 与 2 只需要一个有持仓的账户，不需要本库的任何代码**——所以它们排在最前面，
`cmd/oracle probe` 是嵌套模块里的一个子命令，产出的 JSON 直接成为后续所有版本的离线夹具。
