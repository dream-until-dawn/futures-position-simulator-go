# 版本排期

范围与决策依据见 [design.md](./design.md)，规则依据见 [cn-futures-rules.md](./cn-futures-rules.md)，
可行性依据见 [probes.md](./probes.md)。

## 分支与发布约定

| 分支 | 角色 |
|---|---|
| `main` | 只接受来自 `dev` 的合并，每次合并打 `vX.Y.Z` tag，保持永远可 `go get` |
| `dev` | 默认开发分支，日常提交落这里 |
| `feat/*` `fix/*` | 仅当改动会持续多天且打断 dev 时才开，完事 squash 回 dev |

Go 库特有约束：

- **tag 必须打在 `main` 上**，严格 semver（`v0.1.0`），`go get` 只认这个
- **v1.0.0 之前 API 可自由变更**（v0 不受兼容性承诺约束）——要充分利用这个窗口把 API 打磨定型
- 一旦发布 `v2`，module path 必须加 `/v2` 后缀。**因此 v1.0.0 是一道必须谨慎跨过的门**

⚠️ 本机 `proxy.golang.org` 不可达（[probes.md](./probes.md) §1），
开发与 CI 必须 `go env -w GOPROXY=https://goproxy.cn,direct`。

## 排期原则：证据先于代码

参照项目的经验里，代价最高的缺陷都不是写错公式，而是**把一个猜测当成事实写进了代码**，
然后所有测试都在验证那个猜测。所以本项目的排期有一条硬规则：

> **每个版本先跑判别实验，再写实现。**
> 实验的原始输出存进 `testdata/`，结论写回 cn-futures-rules.md 并把证据等级
> 从「待实测」改成「实测」。**没有实测支撑的规则，代码里要有显式标注和守卫测试。**

cn-futures-rules.md §13 列了 **6 条待实测**，它们全部落在 v0.1.0。
在它们收敛之前，v0.2.0 的核算公式无从确定。

## 对拍的「不建模」必须带到期版本

验收规则是「每个字段要么值对得上，要么写明为什么不建模」。这条规则有个**可以被合法
绕过**的出口，v0.2.0 恰好会撞上：

账户的 `frozen_margin` / `frozen_commission` / `frozen_premium`、持仓的
`volume_*_frozen_*` 与 `order_volume_*` —— 共 11 个字段 —— 要到 v0.4.0 有了
`order` 与冻结才可能实现。于是 v0.2.0 想让对拍全绿，**唯一的路径就是把它们声明成
「不建模」**。而它们恰好是 [silent-risks.md](./silent-risks.md) 第一节第 7 条点名的那批：
报单冻结不建模 → 回测比真实账户「有钱」→ 开得出实际开不出的仓。

⚠️ **声明一旦写下去，没有任何机制逼它在 v0.4.0 被摘掉。** 一个「暂缓」会安静地
变成「永久」，而且是在测试全绿的状态下变的。

因此 `policy.go` 的每条「不建模」**必须带一个到期版本**：

```go
{Field: "frozen_margin", Reason: "报单冻结未实现", NotModeledUntil: "v0.4.0"}
{Field: "premium",       Reason: "期权权利金，v1.0 不覆盖", NotModeledUntil: "never"}
```

对拍工具跑在该版本**之后**仍见到未摘的条目，**判失败**。
把「暂缓」和「永久不建模」在制度上分开，成本是几行代码。
这个机制是 v0.2.0 的交付物之一 —— 它必须和第一条「不建模」同时存在。

## v0.1.0 的判别实验清单

这是当前唯一在跑的版本，它的核心交付物不是代码，是**证据**。
六条实验全部来自 cn-futures-rules.md §13，每条都已写好判别方法：

| # | 问题 | 判别方法 | 阻塞什么 |
|---|---|---|---|
| 1 | 盘中保证金用哪个价 | 持仓不动，等行情走 1%，看保证金是否变；再用「今仓开仓价 ≠ 昨结算价」的一笔分开候选 1 与 2 | `margin` 包的全部公式、可用资金曲线、追保时点 |
| 2 | 盘中持仓盈亏用哪个价 | 持一手昨仓，看盈亏是否随行情变（候选 2 会恒为零） | `pnl` 包、风险度 |
| 3 | 单向大边按品种还是按合约 | **同品种两个不同月份**分别建多空，看合计是 `max(多,空)` 还是 `多+空` | `margin` 的合并范围，跨期套利可能差一倍 |
| 4 | `NoUseHistory` 合约的平仓消耗顺序 | 隔日建昨仓，次日开今仓，平掉**少于昨仓量**的手数（平满了三种顺序同值）。**同时看两个字段**：`Commission` 与 `CloseProfitByDate` —— 后者的差通常比手续费**大一个量级**，更容易把候选分开 | `fee` + **`pnl`** + **`account`**：消耗顺序换一个，平仓盈亏的基线（平昨用昨结算价 / 平今用开仓价）跟着换，当日盈亏与结存链条一并受影响 |
| 5 | 手续费的取整口径 | 构造理论值恰在半分附近的成交，看实际值 | `internal/decimalx`，长周期结存漂移 |
| 6 | 报单被拒的错误码 | 逐项触发八类校验失败 | `ctperr` 的取值 |

**实验 1 与 2 只需要一个有持仓的账户，不需要本库的任何代码**——所以它们排在最前面，
`cmd/probe` 是一个几百行的独立工具，产出的 JSON 直接成为后续所有版本的离线夹具。

## 覆盖缺口（已知，随版本推进逐条消除或转为明确排除）

| 缺口 | 现状 | 计划 |
|---|---|---|
| DCE 日行情端点 | **412 未打通**（probes.md §2） | v0.1.0 尝试另找路径；打不通则在文档里明确标注，由使用者自行提供 |
| 天勤与真实柜台的口径差 | **完全未测量** | v0.8.0 用 SimNow 交叉验并记录差异 |
| 期货公司的保证金加收比例 | 拿不到 | 做成可配置，默认 0，文档写明这会**低估**保证金占用 |
| 套保 / 套利持仓的保证金优惠 | 不做 | 字段第一天就带上，逻辑留到 v1.0 之后 |

## 明确排除在 v1.0 之外

实物交割的仓单流转、连续涨跌停的扩板、**强平的执行**。
