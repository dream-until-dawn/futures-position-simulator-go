# O2：持仓、额度与多挂单冻结适配

依赖O1日历完整性修复，属于全部离线交付目标。旧FrozenBook使用空模拟器逐单FreezeOf并独立Insert，不能借柜台输出的持仓总量推算真实持仓或费用额度。原接口及旧夹具覆盖保留；新增显式状态入口，不把原有真实夹具偷偷替换成合成状态。

## 1 输入与证据边界

新增 `fixture.FrozenBookWithState(f *Fixture, cfg futsim.Config, seed futsim.State, orderedIDs []string) (*order.Book, bool, error)`。seed来自调用者独立的完整重放/结转，必须是挂单重建前的状态（Orders为空、账户冻结为零，序号高水位可非零）；不从f.Positions或f.Account复制待比的输出当输入。Restore按规则版本、交易日、口径、持仓、额度和账户一致性重新校验。

orderedIDs必须是全部有效活单ID的完整有序清单，不能缺、重复、多项或用字典序假装接收顺序。顺序由调用者按业务证据确认，函数只验证完整性，不认证外部时序。缺失委托记录仍返回has=false；记录为空与未记录保持区分。

## 2 唯一核算链与返回

在临时恢复的模拟器上按orderedIDs逐单PlaceAccepted，沿用门面的有效开平标志改写、裸平费用额度、已有挂单扣减、资金冻结和累计可平量校验，不再自行算第二份冻结。失败返回nil簿并丢弃临时实例，不能返回看似完整的前缀；输入seed和夹具不变。

全部接收成功后从Simulator.State提取Orders和LastOrderSequence，经order.RestoreBook构造独立返回簿，保留有效请求、冻结、序号及高水位；不返回可变模拟器或调用者状态的引用。多合约隔离、今昨仓拆分与多单超平由原门面统一判断。

## 3 输入读取与拒绝

沿用已有方向、开平与合约解析器；状态只接受ALIVE/FINISHED，未知不能当终结。ALIVE的剩余手数必须明确提供且为可表示非负整数，已知0表示不再活跃，缺值不能当0；价格和手数均限制指数绝对值至64、系数最多512bit，避免恶意巨大指数分配。活单必须为正手数，不能小数截断或int溢出。正价格必需，未知合约/规格/价格基线/额度、配置和seed交易日不一致、新旧冻结重叠均明确拒绝。原接口的行为兼容不表示它取得了完整持仓证据；需要该能力的调用者必须显式迁移。

## 4 正反例与破坏

合成独立完整seed覆盖：多头/空头、今昨混合、裸平额度与改写、跨合约、多个挂单累计冻结、反向顺序、已有高水位；与直接PlaceAccepted的完整结果比对，并独立手算手数与费用，防止两个路径共同出错。

反例覆盖未知/不一致seed、已有挂单或冻结、错日、重复/缺失/额外顺序、小数/超限手数、第二单超平或资金不足；每种失败核输入完整不变且无返回簿。撤销Restore、顺序覆盖、单笔接入、有效请求保存、手数守卫和高水位保留的破坏必须命中自己的断言。旧实现的空模拟器无法处理改写平今的案例已有明确失败，不把新接口未定义导致的编译失败充作业务红证据。

## 5 验收与兼容

不改StateFormat，不修改CTP工具、安全阀或明日探针构建。新增API登记roadmap并提供独立模块示例；旧真实夹具回归保持原证据来源，新合成测试只证明状态接入和核算行为。锁定源码后完成双模块严格回归、race/fuzz、定向破坏与完整清单，按准确提交封存，不拼接失败轮。

首轮合成正反例通过，独立手算开仓冻结200、合计手续费23，覆盖已有收费额度的平今改写、今昨多空及跨合约隔离。完整状态接入前缀失败不暴露部分簿，输入JSON前后相同；有效订单、显式顺序和空簿高水位均有判据。新增920–933待定向和完整清单；当前尚未宣称O2验收完成。
