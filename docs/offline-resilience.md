# 离线可靠性第二批：设计与验收

基线 main 3fcd231；使用者授权按下列顺序完成，全部验证后自行推送并经 dev 合入 main。本批不访问柜台、不读取凭据、不实施 F9c 撮合、不提升市场规则证据等级。

## 1 验证进程与内容完整性

验证前后记录 HEAD、索引、已跟踪文件的实际字节及状态，不能只比较 porcelain。仓库级排他锁拒绝并行运行；异常遗留锁不自动抢占。命令有总超时，超时与中断清理整个子进程组，日志保留；summary 原子替换，失败不得留下旧成功。正常、已脏文件再次修改、索引变化、超时、子进程、中断和锁冲突分别测试。

## 2 委托生命周期离线回放

对现有一手探针的真实等待器输入可控时间线：重复/延迟/乱序、断线缺失、恢复快照、撤单竞争、提交结果未知。回放不实现交易柜台，不声明支持跨进程自动重发；重启后仅有旧报告而没有本次归属与终态证据必须拒绝收尾。核对报单/撤单引用、终态、成交量及是否允许继续。矛盾回报须拒绝，不能覆盖为成功。

## 3 独立账本扩展

构造多合约、多空、变化价格、两日、不同固定费率与保证金率的合成业务链。使用字面金额/独立整数账本核对权益、平仓/持仓盈亏、保证金与冻结；每阶段 JSON 往返比较全状态，失败完整状态不变。不能只比较两个同源实例。

## 4 性能定位

保留原基线，增加固定次数/多样本采样及 CPU/分配剖析。分析 Restore 的热点后，只优化测得的路径；对完整状态、确定顺序与输入别名隔离做正反向验证。记录同环境前后中位数及分配，未改善则保留诊断而不强行改算法。

## 5 证据复核与当前文档

提供独立命令核对源码提交、清单逐项覆盖与名称/包/测试/预期/断言、唯一性、分类/退出码、报告 SHA256、干净收尾。拒绝篡改、缺项、重复、错误来源和异常轮，不拼接补跑。更新开发手册；原始失败证据保留。

## 最终门槛

Python 验证工具正反例；根模块和 cmd/oracle 无缓存完整回归、race、限时 fuzz；新机制逐项破坏；干净隔离工作树完整破坏扫描（逐项还原，失败立即停）；托管 Windows/Linux CI。记录准确源码提交与原始报告哈希，最终文档提交仅能更改文档。主分支合并后再次检查远端一致与回归，不打 tag。
