# CTP报撤单原生返回码与矛盾回报：后继设计

本批承接已授权的全部剩余交付顺序，依赖九查询源码4a7a340，其34项定向、常规验证和双平台CI已通过、完整1002项正在独立验收；前批完成发布后，先同步准确main及其证书，再锁定本批准确源码验收。本分支可先做离线设计、实证与实现，不提前发布、不改变前批正在扫描的源码。不读取本机真实.env，不创建真实API、不连接柜台、不报撤单到模拟或真实账户。

固定包装的ReqOrderInsert/ReqOrderAction同样清零，虚表偏移分别0xb8/0xd0。用已核真实DLL与本进程假API先复现；绝不调用真实CreateApi/Init，假方法只能回调本进程并记录请求。即时码0不表示最终委托或撤单成功，非零不能覆盖已经观察到的成交、系统编号或未知状态。

## 2 结构与传播

提取Windows私有原生调用内核，复用查询已验收的架构/句柄/编号、偏移、可读指针、执行页及SDK AllocationBase约束；查询保留九方法白名单，订单另用有限枚举仅允许insert/cancel两类。原三种握手路径不改。共享内核没有公开任意偏移入口，静态调用图守卫核它只能由查询/订单白名单包装到达。原34条查询破坏只按迁移后的同一性质调整锚点，不弱化测试。

send仍先执行原安全阀，再唯一分配引用、清理本次格子、调用原生报单；请求编号和投机/今昨字段不改。订单发送与Close同样互斥，关闭后不调用SDK。不新增force/unchecked、重试或序号重置。保留可读报单方法标签，并在原唯一文字路径检查之外增加真实类型化派发调用图约束，防止仅保留标签却绕开安全阀。

新增明确的原生发送错误信息，区分本地绑定失败与SDK即时非零，不把它们塞进柜台ErrorID，也不伪装成交易所拒单。Insert若已分配引用，即使发送报错也同时返回本次引用与已观察状态；不能返回零OrderState抹除一手成交。Cancel/CancelByOrder返回真实调用错误，不改写订单簿为已撤、不清除成交/系统编号、不自动重试。未知仍未知，只有真实回报能改变业务终态。

错误导出为ctp.NativeOrderError，实现error，字段Operation string、Code int32、Local bool；Operation固定insert/cancel，Local明确本地闭锁/绑定失败，Code保留实际SDK int32或本地保留码。使用者可errors.As取得错误，不能用Code覆盖OrderState.ErrorID或据它推断未成交。既有方法签名保持，存档/回放格式不变。

waitOwnedOrder继续只处理本次引用、原有界收尾；撤单调用出错后即使恰好观察到终态，也须把撤单错误传播给上层，保留成交和终态供归属收尾，而不能让流程无错继续开下一单。原价格判据不能在提交不确定时成立。其他历史工具不由本批自动执行，也不借此扩大任何清理范围。

## 3 正反例与破坏验证

旧生产Insert在同步成交回报后底层返回非零应实际先红；旧Cancel即时失败仍nil也应先红。覆盖两方法0/-1/-2/-3/其他非零、指针/编号/开平及数量不改、原生失败保留引用/已成交/系统编号、无回报的未知、错误不写Canceled、不重试，三入口关闭与安全阀拒绝均不能到达假API。两种撤单定位参数分别验证，不拼接会话身份与交易所编号。

以一手执行器合成用例验证取消错误+成交/已撤的所有分支都失败传播，仍保留已见敞口、只收尾、不发下一开仓；金额、手数、安全阀不放宽。新增破坏必须编译通过且命中指定性质，原1002条性质全部保留；失败轮和还原异常完整留存，新准确源码整轮重跑，不拼接旧轮。
